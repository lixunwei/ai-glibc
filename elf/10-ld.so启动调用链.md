# ld.so 动态链接器启动全路径调用链

> 基于 clangd LSP 语义分析获取的精确调用层次，涵盖从内核 execve 到用户 main() 之间
> 动态链接器的完整执行路径。

---

## 一、启动全景图

```
内核 execve()
  → ELF 加载器将控制权交给 ld.so 的 _start (汇编)
    → _dl_start()                                [rtld.c:518]
      → _dl_start_final()                       [rtld.c:446]
        → _dl_sysdep_start() → dl_main()        [rtld.c:1353]
          → 返回用户程序入口地址
            → __libc_start_main() → main()
```

---

## 二、Phase 1: 自举 (_dl_start)

**源文件**: `elf/rtld.c:518-581`

此阶段 ld.so 尚未完成自身重定位，**不能调用任何外部函数**（只能使用 PIC 代码和内联函数）。

```
_dl_start(void *arg)                                [rtld.c:518]
  ├── elf_machine_load_address()                    [dl-machine.h:45]
  │   — 通过 PC-relative 计算获取 ld.so 实际加载地址
  ├── elf_machine_dynamic()                         [dl-machine.h:54]
  │   — 找到 ld.so 自身的 .dynamic 段地址
  ├── elf_get_dynamic_info()                        [get-dynamic-info.h:29]
  │   — 解析 .dynamic 段，填充 l_info[] 数组
  ├── dl_relocate_ld()                              [ldsodefs.h:76]
  │   └── elf_dynamic_do_Rela()                     [do-rel.h:25]
  │       — 处理 ld.so 自身的 RELA 重定位表（自举重定位）
  └── _dl_start_final()                             [rtld.c:446]
```

**关键约束**:
- AArch64 使用 RELA（带显式 addend），不需要读取原始内存
- 自举重定位只处理 `R_AARCH64_RELATIVE` 类型（所有全局变量地址）
- 完成后 ld.so 的全局变量和 GOT 表才可用

## 五、关键设计决策

| 设计点 | 实现 |
|--------|------|
| 自举问题 | _dl_start 使用纯 PIC 代码 + 内联重定位 |
| 内存分配 | 先用 bump allocator，加载 libc 后切换真实 malloc |
| 符号查找顺序 | 广度优先加载 → 深度优先查找（scope 机制） |
| RELRO | 所有重定位完成后才 mprotect，防止 GOT 被覆写 |
| 审计接口 | la_objopen/la_symbind/la_activity 回调 |
| 安全模式 | AT_SECURE=1 时忽略 LD_PRELOAD/LD_LIBRARY_PATH |
| vDSO | 特殊 link_map，不走文件系统加载 |

## 六、与内核的接口

| 内核提供 | 用途 |
|----------|------|
| `AT_PHDR` / `AT_PHNUM` | 主程序 Program Header 位置 |
| `AT_ENTRY` | 主程序入口地址 |
| `AT_BASE` | ld.so 加载基地址 |
| `AT_EXECFN` | 可执行文件路径 |
| `AT_SYSINFO_EHDR` | vDSO 映射地址 |
| `AT_RANDOM` | 16 字节随机数（用于 stack canary、pointer guard） |
| `AT_SECURE` | 是否 setuid/setgid 程序 |
