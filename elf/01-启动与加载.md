# ld.so 启动与 ELF 加载

## 一、ld.so 自举（Bootstrap）

### 问题

动态链接器本身也是共享库，启动时自己的重定位尚未完成。如何在没有任何全局数据/函数可用的情况下完成自身初始化？

### 解决方案：自重定位

**入口**: `sysdeps/x86_64/dl-machine.h:136-176`（`RTLD_START` 汇编宏）

```asm
_start:
  mov %rsp, %rdi          # 内核放置的 argc/argv/envp/auxv
  call _dl_start          # C 函数，返回应用程序入口地址
  jmp *%rax               # 跳转到应用程序 _start
```

### _dl_start

**源文件**: `elf/rtld.c:518-585`

```
_dl_start(arg):
  // 1. 构建临时 bootstrap_map（栈上）
  bootstrap_map.l_addr = elf_machine_load_address()  // PC-relative 计算加载基址
  bootstrap_map.l_ld = elf_machine_dynamic()          // 找到 .dynamic 段

  // 2. 解析自身 .dynamic 段，填充 l_info[]
  elf_get_dynamic_info(bootstrap_map)

  // 3. 对自身执行重定位（此时不能调用任何外部函数）
  ELF_DYNAMIC_RELOCATE(&bootstrap_map, NULL, 0, 0, 0)
  // 只处理 R_X86_64_RELATIVE（不需要符号查找）

  // 4. 自重定位完成，现在可以使用全局变量和函数了
  return _dl_start_final(arg)
```

### 加载基址计算

**源文件**: `sysdeps/x86_64/dl-machine.h:50-64`

```c
static inline ElfW(Addr) elf_machine_load_address(void) {
    // 利用 PC-relative 寻址：运行时地址 - 链接时地址
    extern const ElfW(Ehdr) __ehdr_start;
    return (ElfW(Addr))&__ehdr_start;  // 编译器生成 PC-relative 引用
}
```

## 二、_dl_main — 链接器主逻辑

**源文件**: `elf/rtld.c:1353-2378`

### 整体流程

```
_dl_main(phdr, phnum, user_entry, auxv):
  │
  ├─ 1. 处理环境变量 (LD_PRELOAD, LD_LIBRARY_PATH, LD_BIND_NOW...)
  │     elf/rtld.c:1353-1373
  │
  ├─ 2. 处理可执行文件
  │     ├─ 如果 ld.so 直接运行程序: 映射可执行文件
  │     │   elf/rtld.c:1379-1661
  │     └─ 否则: 从内核传入的 auxv 获取信息
  │         elf/rtld.c:1645-1676
  │
  ├─ 3. rtld_setup_main_map(): 解析可执行文件程序头
  │     elf/rtld.c:1087-1239
  │     - PT_PHDR → phdr 地址
  │     - PT_DYNAMIC → .dynamic 段
  │     - PT_LOAD → 内存映射范围
  │     - PT_TLS → TLS 模板
  │     - PT_GNU_RELRO → RELRO 范围
  │
  ├─ 4. 加载 LD_PRELOAD 库
  │     elf/rtld.c:1818-1836
  │
  ├─ 5. 加载 DT_NEEDED 依赖（BFS）
  │     elf/rtld.c:1942-1950
  │     → _dl_map_object_deps()
  │
  ├─ 6. 重定位所有已加载对象
  │     elf/rtld.c:2034-2045
  │
  └─ 7. 返回应用程序入口地址
```

### 辅助向量 (Auxiliary Vector)

内核通过 auxv 传递关键信息：

| AT 标记 | 含义 | 使用位置 |
|---------|------|---------|
| `AT_PHDR` | 程序头表地址 | 定位可执行文件段 |
| `AT_PHNUM` | 程序头数量 | 遍历 phdr |
| `AT_ENTRY` | 应用程序入口 | _dl_start 返回此地址 |
| `AT_BASE` | ld.so 加载基址 | 自重定位 |
| `AT_EXECFN` | 可执行文件路径 | 错误报告 |
| `AT_RANDOM` | 16 字节随机数 | stack canary / ASLR |
| `AT_HWCAP` | CPU 特性位图 | IFUNC resolver |

## 三、ELF 文件加载

### _dl_map_object_from_fd

**源文件**: `elf/dl-load.c:945-1215`

```
_dl_map_object_from_fd(fd, name, ...):
  │
  ├─ 1. 读取 ELF 头 + 程序头表
  │     elf/dl-load.c:1076-1100
  │
  ├─ 2. 扫描 Program Headers:
  │     ├─ PT_LOAD: 记录 mapstart/mapend/mapoff/prot
  │     │   elf/dl-load.c:1137-1178
  │     ├─ PT_DYNAMIC: 记录 .dynamic 位置
  │     ├─ PT_TLS: 记录 TLS 模板信息
  │     │   elf/dl-load.c:1180-1211
  │     ├─ PT_GNU_RELRO: 记录 RELRO 范围
  │     └─ PT_GNU_STACK: 栈可执行性标志
  │
  ├─ 3. 计算总映射范围
  │     mapstart = 第一个 PT_LOAD 的 p_vaddr (对齐)
  │     mapend   = 最后一个 PT_LOAD 的结束地址
  │
  ├─ 4. mmap 第一个 PT_LOAD 段（含预留总空间）
  │     addr = mmap(NULL, mapend-mapstart, prot, MAP_PRIVATE, fd, offset)
  │     l_addr = addr - mapstart  // 加载偏移
  │
  ├─ 5. mmap 后续 PT_LOAD 段（MAP_FIXED）
  │     for each remaining PT_LOAD:
  │       mmap(l_addr + vaddr, filesz, prot, MAP_FIXED|MAP_PRIVATE, fd, offset)
  │       // BSS: mmap anonymous 或 memset + mprotect
  │
  └─ 6. 创建 link_map，填充字段
        elf_get_dynamic_info(l)  // 解析 .dynamic
```

### PT_LOAD 段映射示意

```
ELF 文件:                           进程地址空间:
┌─────────────┐                    ┌─────────────┐ ← l_addr + phdr[0].p_vaddr
│ PT_LOAD 0   │ (.text/.rodata)    │ r-x 映射    │
│ p_flags=R|X │ ─── mmap ───────→ │             │
├─────────────┤                    ├─────────────┤ ← l_addr + phdr[1].p_vaddr
│ PT_LOAD 1   │ (.data/.bss)       │ rw- 映射    │
│ p_flags=R|W │ ─── mmap ───────→ │             │
└─────────────┘                    └─────────────┘

ASLR: 内核为第一次 mmap(NULL,...) 选择随机基址
l_addr = 实际映射地址 - ELF 中的 p_vaddr
```

## 四、依赖加载（BFS 遍历）

### _dl_map_object_deps

**源文件**: `elf/dl-deps.c:140-240`

```
_dl_map_object_deps(map):
  queue = [map]            // BFS 队列
  
  while queue 非空:
    current = queue.dequeue()
    for each DT_NEEDED in current->l_info:
      name = strtab + DT_NEEDED.d_val
      dep = _dl_map_object(name, ...)   // 查找/加载
      if dep 是新加载的:
        queue.enqueue(dep)
  
  // 构建 l_searchlist（拓扑序）
  map->l_searchlist = 按 BFS 顺序排列的所有依赖
```

### 库搜索路径优先级

```
1. DT_RPATH（已废弃，被 DT_RUNPATH 替代）
2. LD_LIBRARY_PATH 环境变量
3. DT_RUNPATH
4. /etc/ld.so.cache（ldconfig 缓存）
5. 默认路径 /lib, /usr/lib
```

## 五、struct link_map

**源文件**: `include/link.h:95-268`

```c
struct link_map {
    // 调试器可见的基本字段
    ElfW(Addr) l_addr;           // 加载偏移（基址）
    char *l_name;                // 对象绝对路径名
    ElfW(Dyn) *l_ld;            // .dynamic 段指针
    struct link_map *l_next;     // 链表下一个
    struct link_map *l_prev;     // 链表前一个
    
    // 动态段索引（快速访问 DT_* 条目）
    ElfW(Dyn) *l_info[DT_NUM + ...];  // l_info[DT_HASH], l_info[DT_SYMTAB], etc.
    
    // 程序头
    const ElfW(Phdr) *l_phdr;
    ElfW(Addr) l_entry;          // 入口点
    ElfW(Half) l_phnum;          // 程序头数量
    
    // 搜索作用域
    struct r_scope_elem *l_scope[...];
    struct r_scope_elem l_searchlist;   // 该对象的依赖搜索列表
    struct link_map *l_loader;          // 谁加载了我
    
    // 状态标志
    unsigned int l_global:1;     // 在全局作用域中
    unsigned int l_relocated:1;  // 已完成重定位
    unsigned int l_init_called:1; // 构造函数已调用
    
    // 符号查找加速
    Elf_Symndx l_nbuckets;       // GNU hash bucket 数
    Elf32_Word l_gnu_bitmask_idxbits;
    const ElfW(Addr) *l_gnu_bitmask;
    const Elf32_Word *l_gnu_buckets;
    const Elf32_Word *l_gnu_chain_zero;
    
    // TLS
    size_t l_tls_modid;
    size_t l_tls_offset;
    
    // 引用计数
    unsigned int l_direct_opencount;
};
```

### link_map 链表结构

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ ld.so    │←──→│ 可执行文件│←──→│ libc.so  │←──→│ libm.so  │
│ link_map │    │ link_map │    │ link_map │    │ link_map │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
```

## 六、LD_PRELOAD 机制

**源文件**: `elf/rtld.c:1818-1836`

```
处理 LD_PRELOAD:
  解析 LD_PRELOAD 环境变量（冒号/空格分隔）
  for each preload_name:
    _dl_map_object(preload_name, ...)
    标记为全局 (l_global = 1)
  
  // preload 库被插入搜索作用域最前面（在可执行文件之后）
  // 因此它们的符号会覆盖其他库的同名符号
```

### 加载顺序对符号解析的影响

```
搜索顺序: [可执行文件] → [LD_PRELOAD库] → [DT_NEEDED依赖...]

符号查找时第一个匹配胜出 → preload 可拦截任何库函数
```

## 七、TLS (Thread-Local Storage) 设置

当发现 `PT_TLS` 段时：

```
记录 TLS 模板:
  l->l_tls_blocksize = phdr->p_memsz     // TLS 块大小
  l->l_tls_align = phdr->p_align          // 对齐要求
  l->l_tls_initimage = l_addr + p_vaddr   // 初始值模板
  l->l_tls_initimage_size = p_filesz      // 模板大小
  
分配 TLS module ID:
  l->l_tls_modid = ++GL(dl_tls_max_dtv_idx)
```
