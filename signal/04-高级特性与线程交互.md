# 高级特性与线程交互

## 一、sigaltstack — 备用信号栈

### 系统调用包装

glibc 通过 syscalls.list 直接映射到内核 `sigaltstack` 系统调用。

**兼容入口**: `sysdeps/unix/sysv/linux/sigstack.c:24-59`

```c
int sigstack(struct sigstack *ss, struct sigstack *oss)
{
    // 将旧式 sigstack 转换为 stack_t
    stack_t sas, osas;
    sas.ss_sp = ss->ss_sp;
    sas.ss_size = ss->ss_sp - NULL;  // 无法获得真实大小, 估算到地址0的空间
    sas.ss_flags = ss->ss_onstack ? SS_ONSTACK : 0;
    
    result = __sigaltstack(&sas, &osas);
    // 转换回旧式结构
}
```

### stack_t 结构

```c
typedef struct {
    void  *ss_sp;      // 栈基地址
    int    ss_flags;   // SS_DISABLE / SS_ONSTACK
    size_t ss_size;    // 栈大小
} stack_t;
```

### 默认大小

**源文件**: `bits/sigstack.h:26-30`

```c
#define MINSIGSTKSZ  8192                    // 信号栈最小大小
#define SIGSTKSZ     (MINSIGSTKSZ + 32768)   // 推荐信号栈大小 (40960)
```

### 用途

```
正常情况:
  线程栈空间 → 信号到达 → 在当前栈上执行处理器

栈溢出:
  线程栈空间耗尽 → SIGSEGV → 无法在已满的栈上执行!

使用 sigaltstack:
  sigaltstack(alt_stack) → SIGSEGV → 在 alt_stack 上执行处理器 ✓
  
必须配合 sigaction 设置 SA_ONSTACK 标志
```

## 二、信号帧与 ucontext_t

### 内核构建的信号帧（x86_64）

```
用户栈（信号到达时）:
                        ← 原始 RSP
┌─────────────────────┐
│  ucontext_t         │  包含:
│  ├─ uc_mcontext     │    所有通用寄存器 (RAX-R15, RIP, RSP, RFLAGS)
│  ├─ uc_sigmask      │    被阻塞的信号掩码
│  └─ uc_stack        │    信号栈信息
├─────────────────────┤
│  siginfo_t          │  信号来源详细信息
├─────────────────────┤
│  返回地址           │  = __restore_rt 地址
└─────────────────────┘ ← 信号处理器的 RSP
```

### unwind 帧描述

**源文件**: `sysdeps/unix/sysv/linux/x86_64/libc_sigaction.c:54-131`

glibc 为 `__restore_rt` 提供 `.eh_frame` DWARF 信息：
- CFA（Canonical Frame Address）= `ucontext_t.uc_mcontext.gregs[RSP]`
- 每个寄存器的保存位置映射到 ucontext_t 中的对应偏移
- 这使得 libunwind / GDB 能穿越信号帧回溯调用栈

**源文件**: `sysdeps/unix/sysv/linux/x86_64/uw-sigframe.h:38-61`
- 提供 `_Unwind_` 框架使用的辅助函数
- 从 `frame->sp` 获取 `ucontext_t *`，读取 `uc_mcontext` 恢复寄存器

## 三、实时信号

### 内核范围

**源文件**: `sysdeps/unix/sysv/linux/bits/signum-arch.h:61-62`


### 用户可用范围

**源文件**: `signal/allocrtsig.c:26-53`

```c

static int current_rtmax = __SIGRTMAX;                    // 64

int __libc_current_sigrtmin(void) { return current_rtmin; }
int __libc_current_sigrtmax(void) { return current_rtmax; }
```

用户通过 `SIGRTMIN`/`SIGRTMAX` 宏获取（它们是函数调用）：
```c
// signal/signal.h:387-388
#define SIGRTMIN  (__libc_current_sigrtmin())  // 34
#define SIGRTMAX  (__libc_current_sigrtmax())  // 64
```

### NPTL 保留信号

| 信号 | 编号 | 用途 |
|------|------|------|
| `SIGCANCEL` | 32 (`__SIGRTMIN`) | 线程取消 + POSIX 定时器 |
| `SIGSETXID` | 33 (`__SIGRTMIN+1`) | 全线程 setuid/setgid |

### 实时信号 vs 标准信号

| 特性 | 标准信号 (1-31) | 实时信号 (32-64) |
|------|----------------|-----------------|
| 排队 | 不排队（合并） | 排队（不丢失） |
| 顺序 | 不保证 | 编号小的优先 |
| 附带数据 | 无 | `sigqueue` 可带 `sigval` |
| 语义 | 预定义 | 用户自定义 |

## 四、pthread_kill — 向线程发送信号

**源文件**: `nptl/pthread_kill.c:27-101`

实际实现分为三层：

```c
// 第一层：用户 API — 拒绝内部信号
int __pthread_kill(pthread_t threadid, int signo)      // 行 92-101
{
    if (is_internal_signal(signo))
        return EINVAL;
    return __pthread_kill_internal(threadid, signo);
}

// 第二层：内部调用入口
int __pthread_kill_internal(pthread_t threadid, int signo)  // 行 83-90
{
    return __pthread_kill_implementation(threadid, signo, 0);
}

// 第三层：核心实现（行 27-70）
static int __pthread_kill_implementation(pthread_t threadid, int signo, int no_tid)
{
    struct pthread *pd = (struct pthread *)threadid;

    // 快速路径: 向自身发信号
    if (pd == THREAD_SELF) {
        pid_t tid = INTERNAL_SYSCALL_CALL(gettid);
        int ret = INTERNAL_SYSCALL_CALL(tgkill, __getpid(), tid, signo);
        return INTERNAL_SYSCALL_ERROR_P(ret) ? INTERNAL_SYSCALL_ERRNO(ret) : 0;
    }

    // 慢路径: 向其他线程发信号
    // 1. 阻塞所有信号（exit_lock 要求）
    internal_sigset_t old_mask;
    internal_signal_block_all(&old_mask);
    __libc_lock_lock(pd->exit_lock);

    int ret;
    if (pd->exiting)
        // 线程正在退出 → 不发信号（避免 TID 复用）
        ret = no_tid;
    else {
        ret = INTERNAL_SYSCALL_CALL(tgkill, __getpid(), pd->tid, signo);
        ret = INTERNAL_SYSCALL_ERROR_P(ret) ? INTERNAL_SYSCALL_ERRNO(ret) : 0;
    }

    __libc_lock_unlock(pd->exit_lock);
    internal_signal_restore_set(&old_mask);
    return ret;
}
```

**设计要点**:
- 使用 `tgkill`（不是 `tkill`）避免 TID 复用问题
- 通过 `exit_lock` 互斥锁 + `pd->exiting` 标志防止向已退出线程发信号
- 自身发信号走快速路径（不需要加锁）
- 发送信号 0 可以测试线程是否存在

## 五、pthread_sigqueue — 带数据的线程信号

**源文件**: `nptl/pthread_sigqueue.c:28-65`

```c
int __pthread_sigqueue(pthread_t threadid, int signo, const union sigval value)
{
    struct pthread *pd = (struct pthread *)threadid;

    // 验证线程有效
    pid_t tid = atomic_load_relaxed(&pd->tid);
    if (__glibc_unlikely(tid <= 0))
        return ESRCH;

    // 拒绝内部信号（逐个检查而非 is_internal_signal）
    if (signo == SIGCANCEL || signo == SIGTIMER || signo == SIGSETXID)
        return EINVAL;
    
    pid_t pid = getpid();

    // 构造 siginfo_t
    siginfo_t info;
    memset(&info, 0, sizeof(siginfo_t));
    info.si_signo = signo;
    info.si_code = SI_QUEUE;
    info.si_pid = pid;
    info.si_uid = __getuid();
    info.si_value = value;
    
    // rt_tgsigqueueinfo 系统调用
    int val = INTERNAL_SYSCALL_CALL(rt_tgsigqueueinfo, pid, tid, signo, &info);
    return (INTERNAL_SYSCALL_ERROR_P(val)
            ? INTERNAL_SYSCALL_ERRNO(val) : 0);
}
```

## 六、SIGSETXID — 全线程 setuid 同步

### 问题

Linux 中 `setuid()` 仅影响调用线程（内核语义），但 POSIX 要求进程内所有线程
共享凭证（UID/GID）。

### 解决方案

**源文件**: `nptl/nptl_setxid.c:55-93`

```
setuid(newuid):
  1. 主线程向所有其他线程发送 SIGSETXID
  2. 每个线程的 SIGSETXID 处理器:
     a. 验证信号来源 (SI_TKILL + 匹配 PID)
     b. 执行 setuid syscall
     c. 记录错误（如有）
     d. 清除 SETXID 标志
     e. futex_wake 唤醒等待者
  3. 主线程等待所有线程完成
  4. 报告错误（如果任何线程失败）
```

**处理器安装**: 线程创建时通过 `sigaction(SIGSETXID, handler, SA_ONSTACK|SA_SIGINFO|SA_RESTART)`

为什么使用 `SA_ONSTACK`：SIGSETXID 可能在线程使用用户自定义栈时到达，
如果用户栈空间不足，需要在备用栈上执行。

## 七、SIGCANCEL — 线程取消

**源文件**: `nptl/pthread_cancel.c:32-56`

```c
// SIGCANCEL 处理器
static void sigcancel_handler(int sig, siginfo_t *si, void *ctx)
{
    // 验证: 必须是 SIGCANCEL + 同进程 + SI_TKILL
    if (sig != SIGCANCEL
        || si->si_pid != __getpid()
        || si->si_code != SI_TKILL)
        return;
    
    struct pthread *self = THREAD_SELF;
    int oldval = atomic_load_relaxed(&self->cancelhandling);

    // 两种取消触发条件:
    // 1. 异步取消模式 + 取消已启用 + 已被取消
    // 2. 被中断的 PC 在可取消的 syscall 桥代码段内
    if (cancel_enabled_and_canceled_and_async(oldval)
        || cancellation_pc_check(ctx))
    {
        __syscall_do_cancel();
    }
}
```

**处理器安装**（延迟安装，在首次 `pthread_cancel` 调用时）:

```c
// nptl/pthread_cancel.c:70-83
static int init_sigcancel = 0;
if (atomic_load_relaxed(&init_sigcancel) == 0) {
    struct sigaction sa;
    sa.sa_sigaction = sigcancel_handler;
    sa.sa_flags = SA_SIGINFO | SA_RESTART;
    __sigemptyset(&sa.sa_mask);
    __libc_sigaction(SIGCANCEL, &sa, NULL);
    atomic_store_relaxed(&init_sigcancel, 1);
}
```

## 八、abort() — 确保终止

**源文件**: `stdlib/abort.c:73-99`

```c
_Noreturn void abort(void)
{
    // 第一次尝试: 正常发送 SIGABRT
    raise(SIGABRT);

    // 如果处理器返回了（或 SIGABRT 被阻塞/忽略）:
    
    // 加写锁（阻塞所有信号，防止并发修改）
    __abort_lock_wrlock(NULL);

    // 强制设为默认处理（SIG_DFL = 核心转储）
    struct sigaction act = {.sa_handler = SIG_DFL, .sa_flags = 0};
    __sigfillset(&act.sa_mask);
    __libc_sigaction(SIGABRT, &act, NULL);

    // 再次发送
    __pthread_raise_internal(SIGABRT);
    
    // 解除 SIGABRT 阻塞（确保投递）
    internal_signal_unblock_signal(SIGABRT);

    // 不应到达这里，但以防万一:
    ABORT_INSTRUCTION;  // 架构特定的非法指令 (如 ud2)
    _exit(127);
}
```

**"确保终止"逻辑**:
1. `raise(SIGABRT)` — 给用户处理器一个机会（如 cleanup）
2. 如果返回了：强制 SIG_DFL + 再次发送 + 解除阻塞
3. 如果还不死：`ud2` 指令触发 SIGILL → 必然终止
4. 最后兜底：`_exit(127)`
