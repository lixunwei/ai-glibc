# 线程栈空间布局深入分析

## 1. 概述

线程栈是线程执行的核心内存区域。在 glibc/NPTL 中，**初始线程**（main 线程）和
**创建线程**（pthread_create 产生的线程）的栈布局有本质差异：

- **初始线程栈**：由内核在 `execve()` 时分配，位于进程虚拟地址空间的顶部，
  包含 argc、argv、环境变量、辅助向量等信息，大小由 `RLIMIT_STACK` 限制。
- **创建线程栈**：由 glibc 通过 `mmap()` 分配，在末端放置 `struct pthread`
  （TCB）和静态 TLS 块，前端设置 guard page 保护栈溢出。

本文档详细分析两种栈的内存布局、TLS/TCB 定位机制、栈保护策略以及栈缓存复用。

## 2. 初始线程栈布局（内核提供）

### 2.1 execve 后的栈内容

Linux 内核在执行 `execve()` 系统调用时，会在进程虚拟地址空间的高端
分配初始栈，并按照 System V ABI 规范将程序参数和运行环境压入栈中。
栈内容从高地址到低地址排列如下：

```
高地址（栈底）
┌─────────────────────────────────────────────┐
│  信息块 (information block)                  │
│  ├─ 文件名字符串                             │
│  ├─ 环境变量字符串 (env strings)             │
│  └─ 参数字符串 (arg strings)                 │
├─────────────────────────────────────────────┤
│  随机数据 (16 bytes, AT_RANDOM 指向此处)      │
├─────────────────────────────────────────────┤
│  填充 (padding, 使总大小 16 字节对齐)         │
├─────────────────────────────────────────────┤
│  NULL (auxv 终止符, a_type = AT_NULL)        │
│  auxv[n]   { a_type, a_un.a_val }            │
│  ...                                         │
│  auxv[1]   { a_type, a_un.a_val }            │
│  auxv[0]   { a_type, a_un.a_val }            │
├─────────────────────────────────────────────┤
│  NULL (envp 终止符)                          │
│  envp[m]   → 指向环境变量字符串              │
│  ...                                         │
│  envp[0]   → 指向环境变量字符串              │
├─────────────────────────────────────────────┤
│  NULL (argv 终止符)                          │
│  argv[argc-1] → 指向参数字符串               │
│  ...                                         │
│  argv[0]   → 指向程序名字符串                │
├─────────────────────────────────────────────┤
│  argc (参数个数)                             │  ← sp 指向此处
└─────────────────────────────────────────────┘
低地址（栈顶）
```

**关键特征：**
- 每个指针和 argc 在 AArch64 上均为 8 字节
- `sp` 在进入用户态时保证 16 字节对齐
- auxv 数组中每个条目为 `Elf64_auxv_t`（16 字节：8 字节 type + 8 字节 value）
- `AT_RANDOM` 条目的值指向栈上 16 字节的随机数据，用于初始化栈金丝雀

### 2.2 常见辅助向量条目

| AT_类型 | 值 | 含义 |
|---------|-----|------|
| `AT_PHDR` | 3 | 程序头表地址 |
| `AT_PHNUM` | 5 | 程序头表条目数 |
| `AT_PAGESZ` | 6 | 系统页大小 |
| `AT_BASE` | 7 | 解释器（ld.so）基地址 |
| `AT_ENTRY` | 9 | 程序入口点 |
| `AT_RANDOM` | 25 | 16 字节随机数据地址 |
| `AT_HWCAP` | 16 | 硬件能力位掩码 |
| `AT_HWCAP2` | 26 | 扩展硬件能力位掩码 |
| `AT_EXECFN` | 31 | 可执行文件名字符串 |
| `AT_CLKTCK` | 17 | 时钟频率 |

### 2.3 AArch64 `_start` 入口处理

`_start` 是用户态的第一条指令。在 AArch64 上：

```asm
; sysdeps/aarch64/start.S:63-100

ENTRY(_start)
    ; 创建初始帧：清零 FP 和 LR，标志栈底
    mov   x29, #0          ; FP = 0（帧链终止符）
    mov   x30, #0          ; LR = 0（返回地址为空）

    ; 保存 rtld_fini 回调（ld.so 通过 x0 传入）
    mov   x5, x0           ; x5 = rtld_fini

    ; 从栈中读取 argc 和 argv
    ldr   x1, [sp, #0]     ; x1 = argc
    add   x2, sp, 8        ; x2 = &argv[0]

    ; 记录栈边界
    mov   x6, sp           ; x6 = stack_end

    ; 加载 main 函数地址到 x0
    ; ... (PIC/non-PIC 分支)

    mov   x3, #0           ; init（已废弃）
    mov   x4, #0           ; fini（已废弃）

    ; 调用 __libc_start_main(main, argc, argv, init, fini,
    ;                        rtld_fini, stack_end)
    bl    __libc_start_main

    ; 不应到达此处
    bl    abort
```

**寄存器传参约定：**

| 寄存器 | 参数 | 来源 |
|--------|------|------|
| x0 | main 函数指针 | 编译器确定 |
| x1 | argc | `[sp, #0]` |
| x2 | argv | `sp + 8` |
| x3 | init（已废弃） | 0 |
| x4 | fini（已废弃） | 0 |
| x5 | rtld_fini | ld.so 传入的 x0 |
| x6 | stack_end | sp 的值 |

## 3. glibc 初始栈处理

### 3.1 静态链接路径：`__libc_start_main`

对于静态链接的程序（或非 SHARED 路径），`__libc_start_main` 直接处理
`_start` 传递的参数：

```c
// csu/libc-start.c:243-264

// 计算环境变量指针
char **ev = &argv[argc + 1];    // envp = argv 之后跳过 NULL
__environ = ev;                  // 设置全局 __environ

// 记录栈底地址
__libc_stack_end = stack_end;    // = _start 时的 sp 值

// 定位辅助向量
ElfW(auxv_t) *auxvec;
char **evp = ev;
while (*evp++ != NULL)           // 跳过环境变量指针数组
  ;
auxvec = (ElfW(auxv_t) *) evp;  // envp[] 终止 NULL 之后就是 auxv

// 解析辅助向量
_dl_aux_init (auxvec);           // 存储到 GLRO(dl_auxv)
```

### 3.2 动态链接路径：`_dl_sysdep_start`

当程序动态链接时，`ld.so` 先于 `__libc_start_main` 执行：

```c
// elf/rtld.c:489-496
// _dl_start_final() 中：
__libc_stack_end = __builtin_frame_address (0);
start_addr = _dl_sysdep_start (arg, &dl_main);

// sysdeps/unix/sysv/linux/dl-sysdep.c:76-103
// _dl_sysdep_parse_arguments() 中：
_dl_argc  = (intptr_t) *start_argptr;         // 行 79
_dl_argv  = (char **) (start_argptr + 1);     // 行 80
_environ  = _dl_argv + _dl_argc + 1;          // 行 81
// 扫描 envp 找到 auxv：
for (char **tmp = _environ; ; ++tmp)
  if (*tmp == NULL) {
    GLRO(dl_auxv) = (ElfW(auxv_t) *) (tmp + 1);  // 行 86
    break;
  }

// _dl_sysdep_start() 中：
__libc_stack_end = DL_STACK_END (start_argptr);   // 行 103
```

### 3.3 `__environ` 和 `getauxval` 的实现

**环境变量**通过全局变量 `__environ` 暴露给应用程序。该指针直接指向初始栈上
的 `envp[]` 数组。`setenv`/`putenv` 等函数可能会重新分配 `environ`，
但初始值始终来自栈上数据。

**`getauxval()`** 的实现（`misc/getauxval.c:23-66`）：
- `AT_HWCAP`/`AT_HWCAP2` 直接从 `GLRO(dl_hwcap)`/`GLRO(dl_hwcap2)` 读取
  （这些值可能已被处理/增强）
- 其他类型线性扫描 `GLRO(dl_auxv)` 数组查找

```c
// misc/getauxval.c:23-51
bool __getauxval2 (unsigned long int type, unsigned long int *result)
{
  if (type == AT_HWCAP) {
    *result = GLRO(dl_hwcap);
    return true;
  } else if (type == AT_HWCAP2) {
    *result = GLRO(dl_hwcap2);
    return true;
  }
  // 线性扫描 auxv 数组
  for (p = GLRO(dl_auxv); p->a_type != AT_NULL; p++)
    if (p->a_type == type) {
      *result = p->a_un.a_val;
      return true;
    }
  return false;
}
```

**注意：** `GLRO(dl_auxv)` 指针直接指向初始栈上的 auxv 数组数据，没有复制
到堆上。因此初始栈上的 auxv 区域在整个进程生命周期内必须保持有效。

### 3.4 `_dl_aux_init` 解析

```c
// elf/dl-support.c:225-259
void _dl_aux_init (ElfW(auxv_t) *av)
{
  _dl_auxv = av;                          // 保存指向栈上 auxv 的指针
  // 解析所有 auxv 条目到 auxv_values[] 数组
  _dl_parse_auxv (av, auxv_values);
  // 提取关键信息
  _dl_phdr  = (void*) auxv_values[AT_PHDR];
  _dl_phnum = auxv_values[AT_PHNUM];
}
```

## 4. 创建线程栈布局

### 4.1 `allocate_stack` 总体流程

`allocate_stack()` 是 NPTL 分配线程栈的核心函数（`nptl/allocatestack.c:356-658`）。
其主要步骤：

1. 确定栈大小（用户指定或默认值）
2. 计算 guard page 大小（页对齐，不小于 `ARCH_MIN_GUARD_SIZE`）
3. 尝试从栈缓存中获取匹配的栈
4. 缓存未命中时调用 `mmap()` 分配新内存
5. 在 mmap 区域末端放置 `struct pthread` 和 TLS 区域
6. 设置 guard page 保护
7. 分配 DTV（动态 TLS 向量）
8. 将栈加入 `dl_stack_used` 链表

### 4.2 mmap 区域整体布局（AArch64）

AArch64 使用 `TLS_DTV_AT_TP` 模型（TP 指向线程块起始处），栈向下增长。
mmap 区域从低地址到高地址的布局：

```
低地址                                                         高地址
┌────────────┬──────────────────────┬──────────────┬───────────┐
│ guard page │   可用栈空间          │ struct       │ tcbhead_t │
│            │   (向下增长 ↓)        │ pthread      │ + 静态    │
│ guardsize  │                      │              │ TLS 块    │
│ 字节       │                      │ (TLS_PRE_    │           │
│            │                      │  TCB_SIZE)   │ (tls_     │
│            │                      │              │ static_   │
│            │                      │              │  size)    │
└────────────┴──────────────────────┴──────────────┴───────────┘
^            ^                      ^              ^
mem       mem+guardsize            pd           TP = pd + 1
                                                (TPIDR_EL0)
             |←  stacksize 报告值  →|
             |←        size (mmap 总大小)                     →|
```

### 4.3 关键地址计算

**pd（struct pthread 描述符）定位：**

```c
// nptl/allocatestack.c:527-531
pd = (struct pthread *) ((((uintptr_t) mem + size
                            - tls_static_size_for_stack)
                            & ~tls_static_align_m1)
                           - TLS_PRE_TCB_SIZE);
```

计算过程拆解：
1. `mem + size`：mmap 区域的顶部
2. `- tls_static_size_for_stack`：减去静态 TLS 总大小（含 tcbhead_t）
3. `& ~tls_static_align_m1`：向下对齐到 TLS 对齐要求
4. `- TLS_PRE_TCB_SIZE`：再减去 `sizeof(struct pthread)`，得到 pd 地址

**TP（线程指针）定位：**

```c
// sysdeps/aarch64/nptl/tls.h:78
#define TLS_DEFINE_INIT_TP(tp, pd)  void *tp = (pd) + 1
```

TP = pd + 1 = pd 地址 + `sizeof(struct pthread)`

**可用栈顶计算：**

```c
// nptl/allocatestack.c:651-655
#elif TLS_DTV_AT_TP
  stacktop = (char *) (pd - 1);
#endif
  *stacksize = stacktop - pd->stackblock;
```

**tls_static_size_for_stack 计算：**

```c
// nptl/nptl-stack.h:58-62
static inline size_t
__nptl_tls_static_size_for_stack (void)
{
  return roundup (GLRO (dl_tls_static_size), GLRO (dl_tls_static_align));
}
```

这个值包含了 `tcbhead_t` 大小加上所有静态链接共享库的 TLS 块大小，
再向上舍入到 TLS 对齐边界。

### 4.4 栈大小确定

```c
// nptl/allocatestack.c:369-378
if (attr->stacksize != 0)
  size = attr->stacksize;                     // 用户通过 attr 指定
else {
  lll_lock (__default_pthread_attr_lock, LLL_PRIVATE);
  size = __default_pthread_attr.internal.stacksize;  // 系统默认值
  lll_unlock (__default_pthread_attr_lock, LLL_PRIVATE);
}
```

默认栈大小通常为 8 MiB（由 `RLIMIT_STACK` 或 `pthread_setattr_default_np`
决定）。最小栈大小要求：

```c
// nptl/allocatestack.c:44-48
#ifndef MINIMAL_REST_STACK
# define MINIMAL_REST_STACK  4096
#endif

// nptl/allocatestack.c:497-502
if (size < ((guardsize + tls_static_size_for_stack
             + MINIMAL_REST_STACK + pagesize_m1)
            & ~pagesize_m1))
  return EINVAL;   // 栈太小
```

最小栈 = guardsize + tls_static_size + 4096，向上页对齐。

### 4.5 栈对齐要求

```c
// nptl/allocatestack.c:39-42
#ifndef STACK_ALIGN
# define STACK_ALIGN  __alignof__ (long double)
#endif

// nptl/descr.h:39-43
#ifndef TCB_ALIGNMENT
# define TCB_ALIGNMENT 32
#elif TCB_ALIGNMENT < 32
# error TCB_ALIGNMENT must be at least 32
#endif
```

AArch64 上 `long double` 为 16 字节，因此 `STACK_ALIGN = 16`。
`TCB_ALIGNMENT = 32`，要求 `struct pthread` 至少 32 字节对齐。

## 5. AArch64 TLS/TCB 内存模型

### 5.1 TLS 变体选择

AArch64 使用 **TLS Variant I（DTV-at-TP）** 模型：

```c
// sysdeps/aarch64/nptl/tls.h:37-38
#define TLS_DTV_AT_TP   1     // TP 指向线程块起始
#define TLS_TCB_AT_TP   0     // 不使用 TCB-at-TP 模型
```

在这个模型中：
- **TP**（Thread Pointer，TPIDR_EL0）指向线程块的起始位置
- **tcbhead_t** 位于 TP 处
- **静态 TLS 块**位于 TP 之后（更高地址）
- **struct pthread** 位于 TP 之前（更低地址）

### 5.2 tcbhead_t 结构

```c
// sysdeps/aarch64/nptl/tls.h:43-47
typedef struct
{
  dtv_t *dtv;       // DTV（动态 TLS 向量）指针
  void *private;    // 保留字段
} tcbhead_t;
```

AArch64 上 `sizeof(tcbhead_t) = 16` 字节。

### 5.3 TLS 相关常量

```c
// sysdeps/aarch64/nptl/tls.h:50-56
#define TLS_INIT_TCB_SIZE   sizeof (tcbhead_t)    // 16
#define TLS_TCB_SIZE        sizeof (tcbhead_t)    // 16
#define TLS_PRE_TCB_SIZE    sizeof (struct pthread)
```

### 5.4 TP 与 struct pthread 的关系

```
                    TLS_PRE_TCB_SIZE
                 ←─────────────────→
┌────────────────┬──────────────────┬──────────────┬──────────────┐
│ ... 可用栈 ... │  struct pthread  │  tcbhead_t   │ 静态 TLS 块  │
│                │                  │  {dtv,priv}  │              │
└────────────────┴──────────────────┴──────────────┴──────────────┘
                 ^                  ^
                 pd                 TP (TPIDR_EL0)
                 = TP - 1          = pd + 1
                 (指针算术)         (指针算术)
```

**核心宏定义：**

```c
// sysdeps/aarch64/nptl/tls.h:74-86

// 设置 TPIDR_EL0 寄存器
#define TLS_INIT_TP(tcbp) \
  ({ __asm __volatile ("msr tpidr_el0, %0" : : "r" (tcbp)); true; })

// clone 时初始化子线程的 TP 值
#define TLS_DEFINE_INIT_TP(tp, pd)  void *tp = (pd) + 1

// 获取当前线程描述符
#define THREAD_SELF \
  ((struct pthread *)__builtin_thread_pointer () - 1)

// 获取当前线程的 DTV
#define THREAD_DTV() \
  (((tcbhead_t *) __builtin_thread_pointer ())->dtv)
```

### 5.5 TLS_TPADJ 宏

`TLS_TPADJ` 将 pd 转换为 TP 值，用于 TLS 初始化 API：

```c
// nptl/descr.h:464-465
#elif TLS_DTV_AT_TP
# define TLS_TPADJ(pd) \
    ((struct pthread *)((char *) (pd) + TLS_PRE_TCB_SIZE))
```

即 `TLS_TPADJ(pd) = (char*)pd + sizeof(struct pthread) = TP`。

### 5.6 DTV 安装

```c
// sysdeps/aarch64/nptl/tls.h:60-61
#define INSTALL_DTV(tcbp, dtvp) \
  (((tcbhead_t *) (tcbp))->dtv = (dtvp) + 1)
```

DTV 指针指向 `dtvp[1]`，而 `dtvp[0]` 存储 DTV 代数计数器，
`dtvp[-1]` 存储 DTV 总长度。

### 5.7 完整的线程内存模型图

```
低地址                                                               高地址
┌──────────┬────────────────────────┬──────────────────┬────────────────────┐
│guard page│   可用栈空间            │  struct pthread  │ tcbhead + TLS 块   │
│(PROT_NONE│   ← sp 从高向低增长    │  (线程描述符)     │                    │
│或 MADV_  │                        │  ~1700+ bytes    │ tcbhead: 16 bytes  │
│GUARD)    │                        │                  │ TLS: 可变大小       │
└──────────┴────────────────────────┴──────────────────┴────────────────────┘
^          ^                        ^                  ^                     ^
mem        guard_end                pd                 TP                 mem+size
|                                   |                  |
|          |← stacksize →|         |                  |
|←            guardsize            →|                  |
                                    |← TLS_PRE_TCB_SIZE →|
                                                       |← tls_static_size →|

TPIDR_EL0 = TP
THREAD_SELF = pd = TP - sizeof(struct pthread)
DTV* = ((tcbhead_t*)TP)->dtv

DTV 布局:
  dtvp[-1]: 总长度 (generation counter)
  dtvp[0]:  代数 (generation)
  dtvp[1]:  模块 1 的 TLS 块指针 ──→ 静态 TLS 区域
  dtvp[2]:  模块 2 的 TLS 块指针 ──→ 动态分配的 TLS
  ...
```

## 6. Guard Page 保护

### 6.1 两种保护模式

glibc 支持两种 guard page 实现（`nptl/descr.h:128-133`）：

```c
enum allocate_stack_mode_t
{
  ALLOCATE_GUARD_MADV_GUARD = 0,   // 优先：内核 madvise 守护
  ALLOCATE_GUARD_PROT_NONE = 1,    // 备选：经典 PROT_NONE
  ALLOCATE_GUARD_USER = 2,         // 用户提供栈，不设 guard
};
```

### 6.2 Guard Page 位置

对于栈向下增长的架构（包括 AArch64），guard page 位于 mmap 区域的
**最低地址处**：

```c
// nptl/allocatestack.c:174-185
static inline char *
guard_position (void *mem, size_t size, size_t guardsize,
                const struct pthread *pd, size_t pagesize_m1)
{
#if _STACK_GROWS_DOWN
  return mem;          // guard 在 mmap 区域起始处
#elif _STACK_GROWS_UP
  return (char *) (((uintptr_t) pd - guardsize) & ~pagesize_m1);
#endif
}
```

### 6.3 `setup_stack_prot` 流程

```c
// nptl/allocatestack.c:191-236
static inline bool
setup_stack_prot (char *mem, size_t size, struct pthread *pd,
                  size_t guardsize, size_t pagesize_m1)
{
  if (guardsize == 0)
    return true;          // 无 guard，直接返回

  char *guard = guard_position (...);

  // 策略 1：尝试 MADV_GUARD_INSTALL（Linux 6.13+）
  if (allocate_stack_mode == ALLOCATE_GUARD_MADV_GUARD) {
    if (__madvise (guard, guardsize, MADV_GUARD_INSTALL) == 0) {
      pd->stack_mode = ALLOCATE_GUARD_MADV_GUARD;
      return true;
    }
    // 内核不支持，回退到 PROT_NONE
    atomic_store_relaxed (&allocate_stack_mode,
                          ALLOCATE_GUARD_PROT_NONE);
    if (__mprotect (guard, guardsize, PROT_NONE) != 0)
      return false;
  }
  // 策略 2：PROT_NONE
  else {
    const int prot = GL(dl_stack_prot_flags);
    char *guardend = guard + guardsize;
    // 将 guard 之后的区域设为可读写
    if (__mprotect (guardend, size - guardsize, prot) != 0)
      return false;
  }

  pd->stack_mode = ALLOCATE_GUARD_PROT_NONE;
  return true;
}
```

**两种策略的区别：**

| 特性 | MADV_GUARD_INSTALL | PROT_NONE |
|------|-------------------|-----------|
| 内核要求 | Linux 6.13+ | 任意版本 |
| 内存开销 | 无额外页表项 | 需要独立 VMA |
| mmap 标志 | 整个区域一次性 RW | 先 PROT_NONE 再分段 mprotect |
| VMA 合并 | 更友好 | 可能产生 VMA 碎片 |
| 信号 | SIGSEGV（与 PROT_NONE 相同） | SIGSEGV |

### 6.4 Guard 大小计算

```c
// nptl/allocatestack.c:489-496
guardsize = (attr->guardsize + pagesize_m1) & ~pagesize_m1;  // 页对齐
reported_guardsize = guardsize;
if (guardsize > 0 && guardsize < ARCH_MIN_GUARD_SIZE)
  guardsize = ARCH_MIN_GUARD_SIZE;     // 不低于架构最小值
```

默认 guard 大小通常为一个页（4 KiB 或 64 KiB，取决于系统页大小）。

## 7. 栈金丝雀与指针保护

### 7.1 栈金丝雀（Stack Canary）初始化

栈金丝雀用于检测栈缓冲区溢出。它从内核提供的 `AT_RANDOM` 随机数据生成：

```c
// sysdeps/unix/sysv/linux/dl-osinfo.h:25-46
static inline uintptr_t
_dl_setup_stack_chk_guard (void *dl_random)
{
  union {
    uintptr_t num;
    unsigned char bytes[sizeof (uintptr_t)];
  } ret;
  memcpy (ret.bytes, dl_random, sizeof (ret));   // 复制 8 字节随机数据
  ret.num &= ~(uintptr_t) 0xff;                 // 最低字节清零
  // 最低字节为 0 是为了防止通过字符串操作泄露金丝雀值
  return ret.num;
}
```

### 7.2 AArch64 上的存储位置

AArch64 **没有定义** `THREAD_SET_STACK_GUARD` 宏，因此栈金丝雀存储在
全局变量中，而非 TLS：

```c
// csu/libc-start.c:47-51（非 SHARED 路径）
#ifndef THREAD_SET_STACK_GUARD
uintptr_t __stack_chk_guard attribute_relro;
#endif

// csu/libc-start.c:287-292
uintptr_t stack_chk_guard = _dl_setup_stack_chk_guard (_dl_random);
#ifdef THREAD_SET_STACK_GUARD
  THREAD_SET_STACK_GUARD (stack_chk_guard);     // x86 等架构
#else
  __stack_chk_guard = stack_chk_guard;           // AArch64 走此路径
#endif
```

动态链接路径类似（`elf/rtld.c:817-824`）：

```c
// elf/rtld.c:817-824
static void security_init (void)
{
  uintptr_t stack_chk_guard = _dl_setup_stack_chk_guard (_dl_random);
#ifdef THREAD_SET_STACK_GUARD
  THREAD_SET_STACK_GUARD (stack_chk_guard);
#else
  __stack_chk_guard = stack_chk_guard;           // 全局变量
#endif
```

**注意：** 与 x86/x86_64 不同（它们通过 `%fs:%gs` 段寄存器从 TLS 读取
金丝雀），AArch64 上金丝雀是全局变量 `__stack_chk_guard`。编译器生成的
栈保护代码会读取这个全局变量来设置和检查金丝雀值。

### 7.3 指针保护（Pointer Guard）

指针保护用于加密存储在内存中的函数指针（如 `atexit` 注册的回调、
`longjmp` 缓冲区等），防止通过信息泄露直接覆盖函数指针。

```c
// sysdeps/unix/sysv/linux/dl-osinfo.h:48-54
static inline uintptr_t
_dl_setup_pointer_guard (void *dl_random, uintptr_t stack_chk_guard)
{
  uintptr_t ret;
  memcpy (&ret, (char *) dl_random + sizeof (ret), sizeof (ret));
  // 使用 AT_RANDOM 的后 8 字节（与金丝雀使用的前 8 字节不同）
  return ret;
}

// csu/libc-start.c:299-306
uintptr_t pointer_chk_guard = _dl_setup_pointer_guard (
    _dl_random, stack_chk_guard);
#ifdef THREAD_SET_POINTER_GUARD
  THREAD_SET_POINTER_GUARD (pointer_chk_guard);
#else
  __pointer_chk_guard_local = pointer_chk_guard;
#endif
```

## 8. 栈缓存与复用

### 8.1 缓存机制概述

线程退出后，其栈不会立即释放（munmap），而是被放入**栈缓存**
（`GL(dl_stack_cache)`）供后续线程复用。这避免了频繁的 mmap/munmap
系统调用开销。

缓存上限默认为 40 MiB：

```c
// nptl/nptl-stack.c:23
size_t __nptl_stack_cache_maxsize = 40 * 1024 * 1024;
```

### 8.2 从缓存获取栈：`get_cached_stack`

```c
// nptl/allocatestack.c:59-139
static struct pthread *
get_cached_stack (size_t *sizep, void **memp)
{
  size_t size = *sizep;
  struct pthread *result = NULL;

  lll_lock (GL (dl_stack_cache_lock), LLL_PRIVATE);

  // 遍历缓存，寻找大小 >= 请求且最小的栈
  list_for_each (entry, &GL (dl_stack_cache)) {
    curr = list_entry (entry, struct pthread, list);
    if (__nptl_stack_in_use (curr) && curr->stackblock_size >= size) {
      if (curr->stackblock_size == size) {
        result = curr;    // 精确匹配，直接使用
        break;
      }
      // 记录最小匹配
      if (result == NULL || result->stackblock_size > curr->stackblock_size)
        result = curr;
    }
  }

  // 如果差异超过 4 倍，放弃复用
  if (result == NULL || result->stackblock_size > 4 * size) {
    lll_unlock (GL (dl_stack_cache_lock), LLL_PRIVATE);
    return NULL;
  }

  // 从缓存移到使用中列表
  __nptl_stack_list_del (&result->list);
  __nptl_stack_list_add (&result->list, &GL (dl_stack_used));
  GL (dl_stack_cache_actsize) -= result->stackblock_size;

  lll_unlock (GL (dl_stack_cache_lock), LLL_PRIVATE);

  // 重置线程状态
  result->cancelhandling = 0;
  result->cleanup = NULL;
  result->setup_failed = 0;
  result->nextevent = NULL;
  result->exiting = false;
  result->getrandom_buf = NULL;

  // 重新初始化 TLS
  _dl_allocate_tls_init (TLS_TPADJ (result), false);  // 行 148

  return result;
}
```

### 8.3 栈回收：`__nptl_deallocate_stack`

```c
// nptl/nptl-stack.c:121-149
void __nptl_deallocate_stack (struct pthread *pd)
{
  lll_lock (GL (dl_stack_cache_lock), LLL_PRIVATE);

  // 从使用中列表移除
  __nptl_stack_list_del (&pd->list);

  if (pd->stack_mode != ALLOCATE_GUARD_USER)
    // 系统分配的栈：放入缓存
    queue_stack (pd);
  else {
    // 用户提供的栈：只释放 TLS，不释放栈内存
    _dl_deallocate_tls (TLS_TPADJ (pd), false);
  }

  lll_unlock (GL (dl_stack_cache_lock), LLL_PRIVATE);
}
```

### 8.4 缓存溢出处理：`__nptl_free_stacks`

当缓存总大小超过上限时，从末尾开始释放：

```c
// nptl/nptl-stack.c:56-96
void __nptl_free_stacks (size_t limit)
{
  list_for_each_prev_safe (entry, prev, &GL (dl_stack_cache)) {
    curr = list_entry (entry, struct pthread, list);
    if (__nptl_stack_in_use (curr)) {
      __nptl_stack_list_del (entry);
      GL (dl_stack_cache_actsize) -= curr->stackblock_size;
      _dl_deallocate_tls (TLS_TPADJ (curr), false);  // 释放 TLS
      __munmap (curr->stackblock, curr->stackblock_size);  // 释放内存
      if (GL (dl_stack_cache_actsize) <= limit)
        break;
    }
  }
}
```

### 8.5 MADV_DONTNEED 优化

当线程栈被缓存复用时，`advise_stack_range()` 用 `MADV_DONTNEED` 释放
未使用的物理页面，同时保留虚拟地址映射：

```c
// nptl/allocatestack.c:326-349
static __always_inline void
advise_stack_range (void *mem, size_t size, uintptr_t pd, size_t guardsize)
{
  uintptr_t sp = (uintptr_t) CURRENT_STACK_FRAME;
  size_t pagesize_m1 = __getpagesize () - 1;
#if _STACK_GROWS_DOWN
  // 释放 sp 以下、离 mem 较远的页面
  size_t freesize = (sp - (uintptr_t) mem) & ~pagesize_m1;
  if (freesize > PTHREAD_STACK_MIN)
    __madvise (mem, freesize - PTHREAD_STACK_MIN, MADV_DONTNEED);
#endif
}
```

这样，缓存中的栈虽然保留 VMA 映射，但物理页面可以被内核回收。
下次复用时，只有实际触碰的页面才会重新分配物理内存。

### 8.6 VMA 命名

glibc 为线程栈设置 VMA 名称，方便调试：

```c
// nptl/allocatestack.c:661-669
#define SET_STACK_NAME(__prefix, __stack, __stacksize, __tid)  \
  ({                                                           \
    char __stack_name[...];                                     \
    __snprintf (__stack_name, sizeof (__stack_name),             \
                __prefix "%u", (unsigned int) __tid);           \
    __set_vma_name (__stack, __stacksize, __stack_name);        \
  })
```

在 `/proc/<pid>/maps` 中可以看到类似 `[anon:glibc-stack:12345]` 的标记。

## 9. 初始线程与创建线程的差异

| 特性 | 初始线程（main） | 创建线程（pthread_create） |
|------|------------------|--------------------------|
| **栈来源** | 内核 `execve` 时分配 | glibc `mmap()` 分配 |
| **栈位置** | 进程地址空间高端 | 任意位置（mmap 决定） |
| **大小控制** | `RLIMIT_STACK` | `pthread_attr_setstack size` 或默认值 |
| **可增长** | 是（内核自动扩展到 RLIMIT） | 否（mmap 大小固定） |
| **guard page** | 内核管理 | glibc 设置（PROT_NONE/MADV_GUARD） |
| **TCB 位置** | 独立分配（`_dl_allocate_tls_storage`） | 栈内嵌入（mmap 区域末端） |
| **argc/argv/env/auxv** | 在栈上 | 不在栈上 |
| **stackblock** | NULL | mmap 返回的基地址 |
| **栈信息获取** | 解析 `/proc/self/maps` | 直接从 pd->stackblock 读取 |
| **退出回收** | 进程退出时释放 | 放入栈缓存或 munmap |

### 9.1 初始线程栈信息获取

由于初始线程的栈不是 glibc 分配的，其 `pd->stackblock` 为 NULL。
`pthread_getattr_np()` 需要通过读取 `/proc/self/maps` 来获取栈信息：

```c
// nptl/pthread_getattr_np.c:74-155
if (thread->stackblock == NULL) {
  // 初始线程特殊处理
  struct rlimit rl;
  FILE *fp = fopen ("/proc/self/maps", "rce");
  __getrlimit (RLIMIT_STACK, &rl);

  // 将 __libc_stack_end 对齐到页边界
  void *stack_end = (void *) ((uintptr_t) __libc_stack_end
                              & -(uintptr_t) GLRO(dl_pagesize));
  stack_end += GLRO(dl_pagesize);   // 栈向下增长，上调一页

  // 在 /proc/self/maps 中找到包含 __libc_stack_end 的映射
  while (! feof_unlocked (fp)) {
    sscanf (line, "%lx-%lx", &from, &to);
    if (from <= __libc_stack_end && __libc_stack_end < to) {
      iattr->stackaddr = stack_end;
      iattr->stacksize = rl.rlim_cur - (to - stack_end);
      // 不超过实际映射范围
      if (iattr->stacksize > iattr->stackaddr - last_to)
        iattr->stacksize = iattr->stackaddr - last_to;
      break;
    }
  }
}
```

**注意：** 上面代码中的注释提到 "We consider the main process stack to have
ended with the page containing `__libc_stack_end`"。这意味着 argc/argv/env/auxv
所占的空间**不计入**报告的栈大小，以保持 `pthread_getattr_np` 输出的一致性。

### 9.2 初始线程 TCB 的 TLS 分配

初始线程的 TCB 不在栈上，而是通过 `_dl_allocate_tls_storage()` 单独分配
（使用 malloc），然后通过 `TLS_INIT_TP` 设置 TPIDR_EL0 寄存器。
