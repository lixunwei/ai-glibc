# 流生命周期与缓冲管理

## 1. fopen：创建文件流

### 1.1 调用链

```
fopen(filename, mode)
  └→ __fopen_internal(filename, mode, is32=1)    // iofopen.c:56
       ├→ malloc(sizeof(struct locked_FILE))       // 分配流对象
       ├→ _IO_no_init(&fp->file, ...)              // 初始化 FILE 基础字段
       ├→ _IO_JUMPS(&fp) = &_IO_file_jumps         // 设置 vtable
       ├→ _IO_new_file_init_internal(&fp)           // 设置初始标志并链入链表
       └→ _IO_file_fopen((FILE*)fp, filename, mode) // 打开文件
            └→ __fopen_maybe_mmap(&fp->file)        // 只读文件尝试 mmap
```

### 1.2 locked_FILE 结构

`__fopen_internal` 分配的不是单纯的 `_IO_FILE_plus`，而是更大的
`struct locked_FILE`（`iofopen.c:58-65`）：

```c
struct locked_FILE
{
  struct _IO_FILE_plus fp;     // 流本体 + vtable
  _IO_lock_t lock;             // 线程锁
  struct _IO_wide_data wd;     // 宽字符数据
};
```

这种设计将流、锁、宽字符缓冲区分配在同一块连续内存中，
减少 malloc 调用次数。

### 1.3 初始化细节

**`_IO_no_init()`** 设置 FILE 的初始状态：
- `_flags = _IO_MAGIC`（0xFBAD0000）
- `_fileno = -1`（尚未绑定 fd）
- `_mode = 0`（字节/宽字符方向未定）
- 所有缓冲区指针置 NULL
- 设置 `_lock` 指针和 `_wide_data` 指针

**`_IO_new_file_init_internal()`**（`fileops.c:105-116`）：

```c
void _IO_new_file_init_internal (struct _IO_FILE_plus *fp)
{
  fp->file._offset = _IO_pos_BAD;           // 位置未知
  fp->file._flags |= CLOSED_FILEBUF_FLAGS;  // 标记为关闭状态
  _IO_link_in (fp);                          // 加入 _IO_list_all
  fp->file._fileno = -1;                    // fd = -1
}
```

`CLOSED_FILEBUF_FLAGS`（`fileops.c:101-102`）= 
`_IO_IS_FILEBUF + _IO_NO_READS + _IO_NO_WRITES + _IO_TIED_PUT_GET`

### 1.4 实际打开

`_IO_file_fopen()` → `_IO_file_open()`（`fileops.c:224-257`）：
1. 调用 `__open(filename, posix_flags, 0666)` 获取文件描述符
2. 设置 `fp->_fileno = fd`
3. 根据模式清除 `_IO_NO_READS` / `_IO_NO_WRITES`
4. 追加模式时 seek 到文件末尾
5. 调用 `_IO_link_in(fp)` 链入流链表（如尚未链入）

模式解析在 `_IO_new_file_fopen()`（`fileops.c:261-407`）中处理，
包括 `r/w/a/+/b/e(O_CLOEXEC)/x(O_EXCL)/,ccs=CHARSET` 等标志。

## 2. 缓冲管理

### 2.1 三种缓冲模式

| 模式 | 标志 | 行为 |
|------|------|------|
| 全缓冲 `_IOFBF` | 无特殊标志 | 缓冲区满时才刷新 |
| 行缓冲 `_IOLBF` | `_IO_LINE_BUF` | 遇到 `\n` 或缓冲区满时刷新 |
| 无缓冲 `_IONBF` | `_IO_UNBUFFERED` | 每次操作直接读写 |

### 2.2 行缓冲的实现技巧

行缓冲通过一个巧妙的指针操作实现（`fileops.c:822-823`）：

```c
if (f->_mode <= 0 && f->_flags & (_IO_LINE_BUF | _IO_UNBUFFERED))
    f->_IO_write_end = f->_IO_write_ptr;
```

将 `_IO_write_end` 设置为等于 `_IO_write_ptr`，这样下次
`putc()` 时发现 `write_ptr == write_end`（缓冲区"已满"），
会触发 `__overflow` 调用。在 `__overflow` 中检查是否遇到 `\n`，
如果是则刷新（`fileops.c:832-836`）。

### 2.3 默认缓冲区分配

首次读写时如果还没有缓冲区，会触发延迟分配：

```
首次 putc/getc
  → _IO_OVERFLOW / _IO_UNDERFLOW
    → _IO_doallocbuf(fp)
      → _IO_DOALLOCATE(fp)            // vtable 调用
        → _IO_file_doallocate(fp)     // filedoalloc.c:67-96
             ├→ stat(fd) 检查是否是 tty
             │   └→ 如果是 tty，设置 _IO_LINE_BUF
             ├→ malloc(BUFSIZ)         // BUFSIZ = 8192
             └→ _IO_setb(fp, buf, buf+BUFSIZ, 1)
```

如果 `_IO_file_doallocate()` 由于不是文件类型流而没有被调用，
则会回退到 `_IO_default_doallocate()`（`genops.c:503-513`），
直接 `malloc(BUFSIZ)` 分配缓冲区。

### 2.4 setvbuf：用户设置缓冲模式

`setvbuf()` 实现（`iosetvbuf.c:33-95`）：

```c
int _IO_setvbuf (FILE *fp, char *buf, int mode, size_t size)
{
  _IO_acquire_lock (fp);
  switch (mode) {
    case _IOFBF:   // 全缓冲
      fp->_flags &= ~(_IO_LINE_BUF | _IO_UNBUFFERED);
      if (buf == NULL) {
        // 无用户缓冲区，需要立即分配以确保 LINE_BUF 不被后续设置
        if (fp->_IO_buf_base == NULL)
          _IO_DOALLOCATE (fp);
        fp->_flags &= ~_IO_LINE_BUF;
      }
      break;
    case _IOLBF:   // 行缓冲
      fp->_flags &= ~_IO_UNBUFFERED;
      fp->_flags |= _IO_LINE_BUF;
      break;
    case _IONBF:   // 无缓冲
      fp->_flags &= ~_IO_LINE_BUF;
      fp->_flags |= _IO_UNBUFFERED;
      buf = NULL;
      size = 0;
      break;
  }
  if (buf != NULL)
    result = _IO_SETBUF(fp, buf, size);  // 设置用户提供的缓冲区
  _IO_release_lock (fp);
}
```

**关键细节：** 无缓冲模式下，`_IO_default_setbuf()`
（`genops.c:476-494`）会将缓冲区设为 `_shortbuf`（1 字节）：

```c
if (p == NULL || len == 0) {
  fp->_flags |= _IO_UNBUFFERED;
  _IO_setb (fp, fp->_shortbuf, fp->_shortbuf+1, 0);  // 1 字节缓冲
}
```

## 3. fclose：关闭文件流

### 3.1 调用链

```
fclose(fp)
  └→ _IO_new_fclose(fp)                  // iofclose.c:33-87
       ├→ _IO_acquire_lock(fp)
       ├→ _IO_file_close_maybe_unlink(fp) // fileops.c:129-201
       │    ├→ _IO_do_flush(fp)            // 刷新写缓冲
       │    ├→ _IO_SYSCLOSE(fp)            // close(fd)
       │    └→ 清空所有缓冲区指针
       ├→ _IO_release_lock(fp)
       ├→ _IO_un_link(fp)                 // 从链表移除
       ├→ _IO_FINISH(fp)                  // vtable __finish
       ├→ 释放宽字符转换资源（如有）
       ├→ 释放备份缓冲区
       └→ _IO_deallocate_file(fp)         // free()
```

### 3.2 详细流程

**第一阶段：关闭 fd 并刷新（持有流锁）**

`_IO_file_close_maybe_unlink()`（`fileops.c:129-201`）：

```c
int _IO_file_close_maybe_unlink (FILE *fp, bool unlink)
{
  int flush_status = 0;
  // 如果有待写数据，先刷新
  if ((fp->_flags & _IO_NO_WRITES) == 0
      && (fp->_flags & _IO_CURRENTLY_PUTTING) != 0)
    flush_status = _IO_do_flush (fp);
  else if (fp->_fileno >= 0 && /* 有未读数据需要调整文件偏移 */)
    _IO_SEEKOFF (fp, 0, _IO_seek_cur, 0);  // 修正文件位置

  _IO_unsave_markers (fp);
  int close_status = _IO_SYSCLOSE (fp);    // → close(fd)

  // 清空所有缓冲区和指针
  _IO_setb (fp, NULL, NULL, 0);
  _IO_setg (fp, NULL, NULL, NULL);
  _IO_setp (fp, NULL, NULL);

  fp->_flags = _IO_MAGIC | CLOSED_FILEBUF_FLAGS | (fp->_flags & _IO_LINKED);
  fp->_fileno = -1;
  fp->_offset = _IO_pos_BAD;
}
```

**第二阶段：从链表移除（释放流锁后）**

注意 `_IO_un_link()` 在释放流锁之后调用，这保持了正确的锁顺序：
`list_all_lock` → 流锁。这样 `fflush(NULL)` 遍历链表时不会与
fclose 产生死锁。

**第三阶段：销毁与释放**

```c
_IO_FINISH (fp);           // vtable 清理
if (fp->_mode > 0) {
    // 宽字符流：释放 gconv 转换步骤
    __gconv_release_step (cc->__cd_in.step);
    __gconv_release_step (cc->__cd_out.step);
} else {
    // 窄字符流：释放备份区域
    if (_IO_have_backup (fp))
        _IO_free_backup_area (fp);
}
_IO_deallocate_file (fp);  // → free(fp)
```

### 3.3 fclose 中的错误处理

`fclose` 返回 `status`，来自 `_IO_file_close_maybe_unlink` 的返回值。
如果刷新和关闭都失败，优先返回 `close_status`（close 系统调用的错误）。

```c
return close_status ? close_status : flush_status;
```

## 4. _IO_list_all 链表管理

### 4.1 链表结构

```
_IO_list_all → [stderr] → [stdout] → [stdin] → [file1] → [file2] → NULL
                  ↑            ↑          ↑         ↑         ↑
            _prevchain    _prevchain  _prevchain  _prevchain  _prevchain
              指向           指向       指向        指向       指向
           &list_all     &stderr     &stdout     &stdin     &file1
                          ._chain    ._chain     ._chain    ._chain
```

glibc 使用 `_chain` 和 `_prevchain` 构成双向链表（`_prevchain` 
实际指向前一节点的 `_chain` 字段地址），实现 O(1) 的删除操作。

### 4.2 _IO_link_in：插入

`genops.c:107-134`：

```c
void _IO_link_in (struct _IO_FILE_plus *fp)
{
  if ((fp->file._flags & _IO_LINKED) == 0) {
    fp->file._flags |= _IO_LINKED;
    _IO_lock_lock (list_all_lock);   // 全局锁
    _IO_flockfile ((FILE *) fp);     // 流锁

    fp->file._chain = (FILE *) _IO_list_all;  // 新节点指向原头
    fp->file._prevchain = (FILE **) &_IO_list_all;
    if (_IO_list_all != NULL)
      _IO_list_all->file._prevchain = &fp->file._chain;
    _IO_list_all = fp;               // 更新头指针

    _IO_funlockfile ((FILE *) fp);
    _IO_lock_unlock (list_all_lock);
  }
}
```

### 4.3 _IO_un_link：删除

`genops.c:65-104`：

```c
void _IO_un_link (struct _IO_FILE_plus *fp)
{
  if (fp->file._flags & _IO_LINKED) {
    _IO_lock_lock (list_all_lock);
    _IO_flockfile ((FILE *) fp);

    // O(1) 删除：通过 _prevchain 直接修改前驱的 _chain
    FILE **pr = fp->file._prevchain;
    FILE *nx = fp->file._chain;
    *pr = nx;
    if (nx != NULL)
      nx->_prevchain = pr;

    fp->file._flags &= ~_IO_LINKED;

    _IO_funlockfile ((FILE *) fp);
    _IO_lock_unlock (list_all_lock);
  }
}
```

### 4.4 链表遍历场景

| 场景 | 函数 | 行为 |
|------|------|------|
| `fflush(NULL)` | `_IO_flush_all()` | 遍历所有流，刷新写缓冲 |
| `exit()` | `_IO_flush_all()` | 程序退出前刷新所有流 |
| `fcloseall()` | 遍历关闭 | 关闭所有流（GNU 扩展） |
| `fork()` | — | 子进程继承所有流状态 |
