# 核心运行时模块

glibc 的核心运行时模块负责程序启动、动态链接、内存管理和线程支持。

---

## 1. elf — 动态链接器与 ELF 加载

### 功能概述

`elf` 模块实现了 glibc 的动态链接器 (`ld.so`)，负责 ELF 可执行文件和共享库的
加载、重定位、符号解析、审计机制和 TLS（线程局部存储）初始化。

### 规模

- 源文件: 751 个 .c 文件，50 个 .h 文件
- 是 glibc 中最大的模块

### 核心架构

```
┌─────────────────────────────────────────────┐
│              应用程序                         │
├─────────────────────────────────────────────┤
│  dlopen/dlsym/dlclose (用户API)              │
├─────────────────────────────────────────────┤
│  命名空间管理 (dl-open.c)                    │
├─────────────────────────────────────────────┤
│  映射/加载 (dl-load.c)                       │
│  重定位 (dl-reloc.c)                         │
│  符号解析 (dl-lookup.c)                      │
├─────────────────────────────────────────────┤
│  TLS 设置 │ 审计回调 │ 调试接口              │
├─────────────────────────────────────────────┤
│  link_map 链表 / r_debug 调试支持            │
└─────────────────────────────────────────────┘
```

### 关键源文件

| 文件 | 功能 |
|------|------|
| dl-load.c | ELF 文件映射与段加载 |
| dl-open.c | dlopen 主流程编排 |
| dl-close.c | 共享库卸载 |
| dl-lookup.c | 符号查找（哈希表） |
| dl-reloc.c | 重定位处理 |
| dl-sym.c | dlsym 实现 |
| dl-addr.c | dladdr 地址到符号映射 |
| dl-support.c | 静态链接支持 |
| dl-tls.c | 线程局部存储管理 |
| rtld.c | 运行时链接器入口 |
| link.h | `link_map`、`r_debug` 等核心数据结构 |
| elf.h | ELF 格式类型定义 |

### 主要 API

| 函数 | 说明 |
|------|------|
| `dlopen` | 加载共享库 |
| `dlclose` | 关闭共享库 |
| `dlsym` | 查找符号地址 |
| `dlvsym` | 按版本查找符号 |
| `dladdr` / `dladdr1` | 地址反查符号信息 |
| `dlmopen` | 在指定命名空间加载库 |
| `dlinfo` | 查询动态链接信息 |
| `dlerror` | 获取错误信息 |
| `dl_iterate_phdr` | 遍历已加载的程序头 |

### 核心数据结构

- **`link_map`**: 描述一个已加载的共享对象（文件路径、加载地址、段信息、符号表等）
- **`r_debug`**: 调试器接口，通知 GDB 共享库加载/卸载事件
- **`dl_phdr_info`**: `dl_iterate_phdr` 回调参数
- **审计接口**: `la_objopen`, `la_symbind*` 等回调函数

### 依赖关系

- 依赖 `nptl`（TLS 和线程安全）
- 依赖 `sys/mman`（内存映射）
- 被 `dlfcn` 模块包装为用户 API

## 2. malloc — 内存分配器

### 功能概述

glibc 的内存分配器基于 **ptmalloc2**（Doug Lea 的 dlmalloc 的多线程版本），
提供 `malloc`/`free` 等标准内存管理接口。

### 规模

- 源文件: 97 个 .c 文件，8 个 .h 文件

### 核心架构

```
┌─────────────────────────────────────────────┐
│  用户API: malloc/free/realloc/calloc         │
├─────────────────────────────────────────────┤
│  tcache (线程缓存, per-thread)               │
├─────────────────────────────────────────────┤
│  Arena (竞技场)                              │
│  ┌──────────┬──────────┬──────────┐         │
│  │ fastbins │ smallbins│ largebins│         │
│  └──────────┴──────────┴──────────┘         │
├─────────────────────────────────────────────┤
│  Heap 段管理 (sbrk / mmap)                   │
└─────────────────────────────────────────────┘
```

### 关键源文件

| 文件 | 功能 |
|------|------|
| malloc.c | 核心分配器实现（含算法文档） |
| arena.c | 多 Arena 管理逻辑 |
| hooks.c | 调试/检查钩子 |
| malloc.h | 公开 API 声明 |
| thread-freeres.c | 线程退出时资源释放 |
| memusage.c | 内存使用统计工具 |
| mtrace.c | 内存泄漏追踪 |

### 主要 API

| 函数 | 说明 |
|------|------|
| `malloc` | 分配指定大小的内存 |
| `calloc` | 分配并清零内存 |
| `realloc` | 调整已分配内存大小 |
| `reallocarray` | 安全的数组重分配 |
| `free` | 释放内存 |
| `memalign` | 按对齐要求分配 |
| `posix_memalign` | POSIX 对齐分配 |
| `aligned_alloc` | C11 对齐分配 |
| `valloc` / `pvalloc` | 页对齐分配（已废弃） |
| `mallopt` | 调整分配器参数 |
| `mallinfo2` | 获取分配器统计信息 |
| `malloc_trim` | 释放空闲内存回系统 |
| `malloc_usable_size` | 查询可用空间大小 |
| `malloc_stats` | 打印统计信息 |
| `malloc_info` | XML 格式输出分配状态 |

### 关键机制

- **tcache**: 每线程无锁缓存，加速小块分配/释放
- **Arena**: 减少线程间锁竞争，每个 Arena 独立管理 bins
- **Fastbins**: 小于 160 字节的块使用单链表快速分配
- **Unsorted bin**: 释放后暂存，延迟分类
- **mmap 阈值**: 大块直接使用 mmap 分配

### 依赖关系

- 依赖 `elf`（tunables 调优参数）
- 依赖 `nptl`（线程锁、TLS）
- 依赖 `sys/mman`（mmap/munmap）
- 依赖原子操作

## 3. nptl — POSIX 线程库

### 功能概述

NPTL (Native POSIX Threads Library) 是 glibc 的 POSIX 线程实现，
基于 Linux futex 系统调用提供高效的线程同步原语。

### 规模

- 源文件: 326 个 .c 文件，7 个 .h 文件

### 核心架构

```
┌─────────────────────────────────────────────┐
│  POSIX Threads API (pthread_*)               │
├─────────────────────────────────────────────┤
│  线程生命周期                                │
│  (create/join/detach/exit/cancel)            │
├─────────┬───────────────┬───────────────────┤
│  Mutex  │  Condvar      │  Rwlock/Barrier   │
│  互斥锁 │  条件变量      │  读写锁/屏障      │
├─────────┴───────────────┴───────────────────┤
│  Low-level Lock (futex 系统调用)             │
├─────────────────────────────────────────────┤
│  struct pthread (TCB - 线程控制块)           │
│  栈管理 / TLS / 健壮互斥锁列表              │
└─────────────────────────────────────────────┘
```

### 关键源文件

| 文件 | 功能 |
|------|------|
| descr.h | `struct pthread` 定义（线程控制块） |
| pthread_create.c | 线程创建 |
| pthread_join.c | 线程等待 |
| pthread_mutex_lock.c | 互斥锁加锁 |
| pthread_cond_wait.c | 条件变量等待 |
| lowlevellock.c | futex 封装 |
| cancellation.c | 取消点处理 |
| nptl-init.c | 线程库初始化 |
| allocatestack.c | 线程栈分配 |

### 主要 API

| 函数 | 说明 |
|------|------|
| `pthread_create` | 创建新线程 |
| `pthread_join` | 等待线程结束 |
| `pthread_detach` | 分离线程 |
| `pthread_exit` | 终止当前线程 |
| `pthread_cancel` | 取消线程 |
| `pthread_self` | 获取当前线程 ID |
| `pthread_mutex_lock/unlock` | 互斥锁操作 |
| `pthread_cond_wait/signal/broadcast` | 条件变量操作 |
| `pthread_rwlock_rdlock/wrlock/unlock` | 读写锁操作 |
| `pthread_barrier_wait` | 屏障同步 |
| `pthread_key_create` | 线程特定数据 |
| `pthread_setname_np` | 设置线程名称 |
| `pthread_setaffinity_np` | 设置 CPU 亲和性 |

### 核心数据结构

- **`struct pthread`** (descr.h): 线程控制块，包含:
  - 线程 ID、栈信息、TLS 区域
  - 取消状态、清理处理函数链
  - 健壮互斥锁列表
  - 调度参数、CPU 亲和性掩码
  - unwind 信息

### 依赖关系

- 依赖 `elf`（TLS 设置）
- 依赖 futex 系统调用
- 依赖原子操作
- 被 `malloc`、`libio`、`resolv` 等模块使用

## 4. csu — C 启动代码

### 功能概述

`csu` (C Start-Up) 模块提供程序入口点和初始化/终止代码，是连接内核 `execve` 
和用户 `main()` 函数之间的桥梁。

### 规模

- 源文件: 14 个 .c 文件

### 启动流程

```
内核 execve()
    ↓
_start (汇编入口, sysdeps/*/start.S)
    ↓
__libc_start_main (libc-start.c)
    ├── 设置 TLS
    ├── 运行 .init_array / .ctors
    ├── 设置 atexit 钩子
    ↓
main(argc, argv, envp)
    ↓
exit() → .fini_array / .dtors → _exit()
```

### 关键源文件

| 文件 | 功能 |
|------|------|
| libc-start.c | `__libc_start_main` 主初始化流程 |
| init-first.c | 最早期初始化 |
| static-reloc.c | 静态链接重定位支持 |
| gmon-start.c | gprof 启动钩子 |
| abi-note.S | ELF ABI 标记 |

### 生成的目标文件

- **crt1.o** / **Scrt1.o**: 包含 `_start`，动态/静态可执行文件入口
- **crti.o**: `.init` 段前序
- **crtn.o**: `.init` 段后序
- **rcrt1.o**: 相对重定位启动文件

### 依赖关系

- 被所有可执行文件链接使用
- 依赖 `elf` 模块（动态链接器初始化）
- 依赖 `nptl`（TLS 初始化）
