# 网络通信模块

网络通信模块提供从 socket 原语到 DNS 解析的完整网络协议栈用户空间接口。

---

## 1. socket — 套接字接口

### 功能概述

`socket` 模块提供 BSD socket API 的系统调用封装，是所有网络通信的基础。

### 规模

- 源文件: 34 个 .c 文件

### 主要 API

| 函数 | 说明 |
|------|------|
| `socket` | 创建套接字 |
| `socketpair` | 创建套接字对 |
| `bind` | 绑定地址 |
| `connect` | 连接远端 |
| `listen` | 监听连接 |
| `accept` / `accept4` | 接受连接 |
| `send` / `sendto` / `sendmsg` | 发送数据 |
| `sendmmsg` | 批量发送 |
| `recv` / `recvfrom` / `recvmsg` | 接收数据 |
| `recvmmsg` | 批量接收 |
| `getsockopt` / `setsockopt` | 套接字选项 |
| `getsockname` / `getpeername` | 获取地址信息 |
| `shutdown` | 关闭连接方向 |
| `sockatmark` | 检查紧急数据标记 |

### 关键头文件

- `sys/socket.h`: 主要 socket 类型和函数声明
- `sys/un.h`: Unix 域套接字地址
- `bits/socket.h`: 协议族、类型常量
- `net/if.h`: 网络接口

### 实现特点

- 系统调用薄封装
- 消息 I/O 函数支持取消点（unwind）
- fortify 变体用于 `recv` 等

## 2. inet — 互联网协议辅助

### 功能概述

`inet` 模块提供 IPv4/IPv6 地址转换、网络接口查询、以太网地址处理，
以及一些传统网络工具函数（如 `rcmd`/`rexec`）。

### 规模

- 源文件: 56 个 .c 文件，2 个 .h 文件

### 主要 API

| 函数 | 说明 |
|------|------|
| `inet_pton` | 文本地址转二进制 |
| `inet_ntop` | 二进制地址转文本 |
| `inet_addr` / `inet_ntoa` | IPv4 地址转换（旧式） |
| `inet_aton` | 文本转 IPv4 二进制 |
| `htonl` / `htons` / `ntohl` / `ntohs` | 字节序转换 |
| `if_nametoindex` / `if_indextoname` | 接口名/索引转换 |
| `getifaddrs` / `freeifaddrs` | 获取接口地址列表 |
| `ether_aton` / `ether_ntoa` | 以太网地址转换 |
| `getsourcefilter` / `setsourcefilter` | 多播源过滤 |

### 内部架构

- `net-internal.h` 定义了内部超时机制和 IDNA（国际化域名）转换
- IPv6 scope ID 解析
- 支持 deadline 式超时（用于 DNS 查询等长流程）

### 依赖关系

- 依赖 `socket`
- 被 `resolv`、`nss` 使用
- 依赖 `string`（地址格式化）

## 3. resolv — DNS 解析器

### 功能概述

`resolv` 模块实现了完整的 DNS 解析器（resolver），包括查询构建、
响应解析、resolver 状态管理和异步查询支持。

### 规模

- 源文件: 123 个 .c 文件，9 个 .h 文件

### 核心架构

```
┌─────────────────────────────────────────────┐
│  高级 API: getaddrinfo, gethostbyname       │
├─────────────────────────────────────────────┤
│  resolver 上下文 (resolv_context)            │
├─────────────────────────────────────────────┤
│  res_query / res_search / res_send           │
├─────────────────────────────────────────────┤
│  查询构建 (res_mkquery)                      │
│  响应解析 (ns_name_*, ns_rr_cursor_*)       │
├─────────────────────────────────────────────┤
│  传输层: UDP / TCP (带重试和超时)            │
│  配置: /etc/resolv.conf 解析                 │
└─────────────────────────────────────────────┘
```

### 主要 API

| 函数 | 说明 |
|------|------|
| `res_init` | 初始化 resolver |
| `res_query` | 执行 DNS 查询 |
| `res_search` | 带搜索域的 DNS 查询 |
| `res_mkquery` | 构建 DNS 查询报文 |
| `res_send` | 发送 DNS 查询并接收响应 |
| `res_close` | 关闭 resolver |
| `dn_comp` | 域名压缩 |
| `dn_expand` | 域名解压缩 |
| `dn_skipname` | 跳过压缩域名 |
| `ns_name_unpack` / `ns_name_pack` | 域名编解码 |
| `getaddrinfo_a` | 异步地址解析 |
| `gai_cancel` / `gai_suspend` | 异步操作控制 |

### 配置与状态

- **`/etc/resolv.conf`**: nameserver、search、options
- **`resolv_context`**: 每次解析操作的上下文对象
- **关键标志**:
  - `RES_F_VC`: 使用 TCP
  - `RES_F_CONN`: 使用已连接 UDP
  - `RES_F_SNGLKUP`: 串行查询（避免某些防火墙问题）
- **EDNS 缓冲区**: 固定 1200 字节

### 依赖关系

- 依赖 `socket`/`inet`（网络通信）
- 依赖 `nptl`（线程安全）
- 被 `nss` 的 `nss_dns` 模块调用

## 4. nss — 名称服务开关

### 功能概述

NSS (Name Service Switch) 是 glibc 的数据库查找抽象层，将用户/组/主机名等
查询请求路由到可配置的后端模块（如 files、dns、ldap 等）。

### 规模

- 源文件: 182 个 .c 文件，15 个 .h 文件

### 核心架构

```
┌─────────────────────────────────────────────┐
│  应用程序                                    │
│  getpwnam() / gethostbyname() / getaddrinfo()│
├─────────────────────────────────────────────┤
│  NSS 派发层                                  │
│  (解析 /etc/nsswitch.conf 配置)              │
├──────┬──────────┬──────────┬────────────────┤
│ files│   dns    │   ldap   │  其他模块 ...   │
│ 本地 │  DNS解析  │  LDAP    │               │
└──────┴──────────┴──────────┴────────────────┘
```

### 支持的数据库

| 数据库 | 用途 | 典型查询函数 |
|--------|------|-------------|
| passwd | 用户信息 | `getpwnam`, `getpwuid` |
| group | 组信息 | `getgrnam`, `getgrgid` |
| shadow | 密码信息 | `getspnam` |
| hosts | 主机名解析 | `gethostbyname`, `getaddrinfo` |
| services | 服务端口 | `getservbyname` |
| networks | 网络名 | `getnetbyname` |
| protocols | 协议名 | `getprotobyname` |
| ethers | 以太网地址 | `ether_hostton` |
| aliases | 邮件别名 | `getaliasbyname` |
| netgroup | 网络组 | `innetgr` |

### 配置

**`/etc/nsswitch.conf`** 示例:
```
passwd:     files systemd
group:      files systemd
hosts:      files dns myhostname
services:   files
```

### 模块加载机制

- 通过 `dlopen` 按需加载 `libnss_*.so.2`
- 每个模块提供固定接口函数（如 `_nss_files_getpwnam_r`）
- 缓存 `struct nss_module` 和函数指针表
- 支持动作指令: `[SUCCESS=return]`, `[NOTFOUND=continue]` 等

### 主要 API

| 函数 | 说明 |
|------|------|
| `getaddrinfo` / `getnameinfo` | 地址/名称解析（推荐接口） |
| `getpwnam_r` / `getpwuid_r` | 查询用户（可重入） |
| `getgrnam_r` / `getgrgid_r` | 查询组（可重入） |
| `gethostbyname_r` | 主机名查询（旧式，可重入） |
| `getservbyname_r` | 服务端口查询 |
| `initgroups` | 初始化附属组列表 |
| `__nss_configure_lookup` | 程序内配置 NSS |

### 依赖关系

- 依赖 `elf`/`dlfcn`（动态加载模块）
- 依赖 `resolv`（dns 后端）
- 依赖 `nptl`（线程安全）
- 被几乎所有需要用户/主机查询的程序使用

## 5. sunrpc — Sun RPC（遗留）

### 功能概述

`sunrpc` 模块提供 ONC RPC (Open Network Computing Remote Procedure Call) 
实现，包括 XDR 序列化、客户端/服务端框架和端口映射。

> ⚠️ 此模块已标记为遗留代码，新程序应使用 gRPC 或其他现代 RPC 框架。

### 主要 API

| 函数 | 说明 |
|------|------|
| `clnt_create` | 创建 RPC 客户端 |
| `svc_run` | 运行 RPC 服务循环 |
| `xdr_*` | XDR 序列化/反序列化函数族 |
| `authunix_create` | 创建 Unix 认证 |
| `pmap_*` | 端口映射操作 |

### 依赖关系

- 依赖 `socket`/`inet`
- 被 NIS (`nis` 模块) 使用
