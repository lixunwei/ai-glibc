## 详细依赖矩阵

### 被广泛依赖的模块（基础模块）

| 模块 | 被依赖者 | 说明 |
|------|----------|------|
| **string** | 几乎所有模块 | 基础字符串/内存操作 |
| **malloc** | 大部分模块 | 动态内存分配 |
| **nptl** | libio, malloc, resolv, nss, ... | 线程安全/锁 |
| **elf** | csu, dlfcn, nss, malloc | 动态链接/TLS |
| **sysdeps** | 所有模块 | 架构特定实现 |
| **csu** | 所有可执行文件 | 启动代码 |

### 核心模块的依赖

| 模块 | 依赖 |
|------|------|
| elf | nptl(TLS), sys/mman, string |
| malloc | elf(tunables), nptl(锁), sys/mman, 原子操作 |
| nptl | elf(TLS), futex 系统调用, 原子操作 |
| libio | nptl(锁), io(系统调用), locale, iconv |
| stdio-common | libio, locale, math, string, malloc |
| nss | elf/dlfcn(dlopen), resolv, nptl |
| resolv | socket, inet, nptl |

### 模块分层（从底到高）

```
第 0 层 (内核接口):  sysdeps, 系统调用
第 1 层 (核心):      string, malloc, nptl, elf, csu
第 2 层 (基础库):    io, locale, ctype, math, time, signal
第 3 层 (高级库):    libio, stdio-common, socket, inet
第 4 层 (服务):      resolv, nss, iconv, intl, wcsmbs
第 5 层 (应用):      dlfcn, login, nscd, sunrpc, nis
```

## 循环依赖处理

glibc 中存在一些不可避免的循环依赖:

1. **malloc ↔ nptl**: malloc 需要锁，nptl 需要 malloc 分配栈
   - 解决: 初始化阶段使用特殊路径避免死锁

2. **elf ↔ nptl**: elf 需要 TLS 支持，TLS 依赖 elf 加载
   - 解决: 静态链接 TLS 初始化代码到 ld.so

3. **libio ↔ malloc**: printf 需要 malloc，malloc 的错误报告需要 printf
   - 解决: malloc 使用低级 write() 输出错误

## 编译产物

| 库文件 | 包含的模块 |
|--------|-----------|
| `ld-linux-x86-64.so.2` | elf (动态链接器) |
| `libc.so.6` | 大部分模块（string, malloc, io, stdio, nptl, locale, ...） |
| `libm.so.6` | math |
| `librt.so.1` | rt (实时扩展) |
| `libdl.so.2` | dlfcn (兼容性，已合并入 libc) |
| `libpthread.so.0` | nptl (兼容性，已合并入 libc) |
| `libresolv.so.2` | resolv |
| `libnss_*.so.2` | nss 后端模块 |
| `libnsl.so.1` | nis/sunrpc |
| `libthread_db.so.1` | nptl_db |

> 注: 从 glibc 2.34 开始，libpthread、libdl、librt 等已合并入 libc.so。
