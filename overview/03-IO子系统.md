# I/O 子系统模块

I/O 子系统负责文件操作、流缓冲和格式化输入输出。

---

## 1. libio — FILE 流引擎

### 功能概述

`libio` 是 glibc 的内部 FILE 流实现层，提供带缓冲的文件 I/O 操作。
它实现了 `_IO_FILE` 结构和基于虚函数表（vtable）的派发机制，
支持窄字符流、宽字符流、内存流和 cookie 流。

### 规模

- 源文件: 231 个 .c 文件，6 个 .h 文件

### 核心架构

```
┌─────────────────────────────────────────────┐
│  用户 API: fopen, fread, fwrite, fclose ...  │
├─────────────────────────────────────────────┤
│  _IO_FILE 结构 (缓冲区、状态标志)            │
├─────────────────────────────────────────────┤
│  vtable (跳转表)                             │
│  ┌──────────┬──────────┬──────────┐         │
│  │ 文件流   │ 内存流   │ cookie流 │         │
│  │ _IO_file │ _IO_str  │ _IO_cook │         │
│  └──────────┴──────────┴──────────┘         │
├─────────────────────────────────────────────┤
│  宽字符支持 (_IO_wide_data)                  │
├─────────────────────────────────────────────┤
│  底层 I/O (read/write/lseek 系统调用)        │
└─────────────────────────────────────────────┘
```

### 关键源文件

| 文件 | 功能 |
|------|------|
| libio.h | `_IO_FILE` 结构定义、标志位 |
| libioP.h | 内部 vtable 架构、宏定义 |
| stdio.h | 公开 API 声明 |
| fileops.c | 文件流的 vtable 实现 |
| wfileops.c | 宽字符文件流操作 |
| strops.c | 内存流操作 |
| iofopen.c | fopen 实现 |
| iofclose.c | fclose 实现 |
| iofread.c / iofwrite.c | fread/fwrite 实现 |
| genops.c | 通用流操作 |

### 主要 API

| 函数 | 说明 |
|------|------|
| `fopen` / `fopen64` | 打开文件流 |
| `fdopen` | 从文件描述符创建流 |
| `freopen` | 重新打开流 |
| `fclose` | 关闭流 |
| `fread` / `fwrite` | 块读写 |
| `fgetc` / `fputc` | 字符读写 |
| `fgets` / `fputs` | 行读写 |
| `fseek` / `ftell` / `rewind` | 流定位 |
| `fflush` | 刷新缓冲区 |
| `setvbuf` / `setbuf` | 设置缓冲模式 |
| `ungetc` | 回推字符 |
| `fmemopen` / `open_memstream` | 内存流 |
| `fopencookie` | 自定义 I/O 流 |
| `getwc` / `putwc` / `fgetws` | 宽字符流操作 |

### 核心数据结构

**`_IO_FILE`** 主要字段:
- 读/写缓冲区指针 (`_IO_read_ptr/end/base`, `_IO_write_ptr/end/base`)
- 文件描述符 (`_fileno`)
- 标志位 (`_flags`: 读/写/追加/EOF/错误等)
- vtable 指针（指向操作函数表）
- 锁 (`_lock`): 多线程安全
- 宽字符数据 (`_wide_data`)

### 安全机制

- **vtable 验证**: 防止通过覆盖 vtable 指针进行攻击
- **`_IO_FLAGS2_NEED_LOCK`**: 控制是否需要加锁
- **fortify 检查**: `_chk` 变体函数

### 依赖关系

- 被 `stdio-common` 调用
- 依赖 `nptl`（流锁定）
- 依赖系统调用（read/write/lseek/mmap）
- 依赖 `locale`/`iconv`（宽字符转换）

## 2. io — 低级文件 I/O

### 功能概述

`io` 模块提供 POSIX 级别的文件描述符操作接口，是对 Linux 系统调用的
直接封装，包括文件打开、读写、元数据操作和目录遍历。

### 规模

- 源文件: 182 个 .c 文件，8 个 .h 文件

### 功能分类

```
io
├── 文件打开/关闭: open, openat, close, creat
├── 读写: read, write, pread, pwrite, copy_file_range
├── 定位: lseek, lseek64
├── 元数据: stat, fstat, lstat, fstatat, chmod, chown
├── 链接: link, symlink, readlink, unlink, rename
├── 目录: mkdir, rmdir, chdir, getcwd
├── 文件描述符: dup, dup2, dup3, pipe, fcntl
├── 轮询: poll, ppoll, select, pselect
├── 遍历: ftw, nftw, fts
└── 访问控制: access, faccessat
```

### 主要 API

| 函数 | 说明 |
|------|------|
| `open` / `openat` | 打开文件 |
| `close` | 关闭文件描述符 |
| `read` / `write` | 基本读写 |
| `pread` / `pwrite` | 指定偏移读写 |
| `lseek` | 移动文件偏移 |
| `stat` / `fstat` / `lstat` | 获取文件信息 |
| `chmod` / `fchmod` | 修改权限 |
| `chown` / `fchown` | 修改所有者 |
| `link` / `symlink` / `readlink` | 链接操作 |
| `unlink` / `remove` / `rename` | 删除/重命名 |
| `mkdir` / `rmdir` | 目录创建/删除 |
| `dup` / `dup2` / `dup3` | 复制文件描述符 |
| `pipe` / `pipe2` | 创建管道 |
| `fcntl` | 文件描述符控制 |
| `poll` / `ppoll` | I/O 多路复用 |
| `sendfile` / `copy_file_range` | 零拷贝传输 |
| `ftw` / `nftw` | 文件树遍历 |
| `fts_open` / `fts_read` | 文件层次遍历 |

### 实现特点

- 大部分是 **系统调用的薄封装**
- 提供 32 位和 64 位两套接口（`stat` vs `stat64`）
- `*at` 系列函数（相对目录 fd 操作）
- fortify 变体（`__read_chk` 等）
- 取消点支持（`read`/`write`/`open` 等为取消点）
- time64 兼容（`utimensat` 等）

### 关键头文件

| 头文件 | 内容 |
|--------|------|
| fcntl.h | 文件控制标志和 `fcntl` |
| sys/stat.h | 文件状态结构和函数 |
| poll.h | `poll`/`ppoll` |
| fts.h | 文件层次遍历 |
| ftw.h | 文件树遍历 |
| utime.h | 文件时间修改 |

### 依赖关系

- 直接封装 Linux 系统调用
- 被 `libio`、`dirent` 等上层模块使用
- 依赖 `nptl`（取消点机制）
- 依赖 `debug`（fortify 检查）
