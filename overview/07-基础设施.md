# 基础设施模块

基础设施模块提供底层支持功能：调试、性能分析、架构适配等。

---

## 1. debug — 调试与安全强化

### 功能概述

`debug` 模块实现了 `_FORTIFY_SOURCE` 安全检查、栈溢出保护、
回溯追踪等调试辅助功能。

### 规模

- 源文件: 116 个 .c 文件，2 个 .h 文件

### 功能分类

```
debug
├── Fortify 检查: *_chk 系列（带边界检查的函数包装）
├── 栈保护: __stack_chk_fail, __stack_chk_fail_local
├── 回溯: backtrace, backtrace_symbols, backtrace_symbols_fd
└── 强化失败: __fortify_fail (统一错误报告)
```

### 主要 API

| 函数 | 说明 |
|------|------|
| `backtrace` | 获取当前调用栈 |
| `backtrace_symbols` | 将地址转为符号字符串 |
| `backtrace_symbols_fd` | 直接输出符号到文件描述符 |
| `__fortify_fail` | fortify 检查失败时调用 |
| `__stack_chk_fail` | 栈金丝雀检查失败 |
| `__*_chk` | 各种带检查的函数变体 |

### Fortify 保护的函数（部分）

- `memcpy_chk`, `memmove_chk`, `memset_chk`
- `strcpy_chk`, `strncpy_chk`, `strcat_chk`
- `sprintf_chk`, `snprintf_chk`, `vsprintf_chk`
- `read_chk`, `recv_chk`, `recvfrom_chk`
- `gets_chk`, `fgets_chk`, `fread_chk`
- `realpath_chk`, `getcwd_chk`

### 工作原理

```c
// 编译器将:
memcpy(dest, src, n);
// 在 _FORTIFY_SOURCE=2 时替换为:
__memcpy_chk(dest, src, n, __bos(dest));
// __bos(dest) = 编译器计算的 dest 缓冲区大小
// 如果 n > __bos(dest)，运行时 abort
```

## 2. sysdeps — 架构适配层

### 功能概述

`sysdeps` 是 glibc 最重要的基础设施目录，包含所有平台相关的代码实现。
通过目录搜索路径机制，使同一接口在不同操作系统和处理器架构上有最优实现。

### 目录结构

```
sysdeps/
├── generic/          ← 通用 C 实现（最终 fallback）
├── unix/
│   └── sysv/
│       └── linux/    ← Linux 特有实现
│           ├── x86_64/
│           ├── aarch64/
│           ├── riscv/
│           └── ...
├── x86_64/           ← x86_64 架构优化
│   ├── multiarch/    ← 运行时 CPU 特性检测分发
│   ├── fpu/          ← 浮点运算
│   └── 64/           ← 纯 64 位
├── aarch64/          ← ARM64 优化
├── ieee754/          ← IEEE-754 浮点通用实现
├── posix/            ← POSIX 通用实现
├── pthread/          ← pthread 通用实现
├── nptl/             ← NPTL 核心
├── mach/             ← Mach 微内核
│   └── hurd/         ← GNU Hurd
└── htl/              ← Hurd Thread Library
```

### 搜索机制

glibc 构建系统按照 **最具体到最通用** 的顺序搜索实现:

```
sysdeps/unix/sysv/linux/x86_64/64/    (最具体)
sysdeps/unix/sysv/linux/x86_64/
sysdeps/unix/sysv/linux/x86/
sysdeps/unix/sysv/linux/
sysdeps/x86_64/multiarch/
sysdeps/x86_64/64/
sysdeps/x86_64/
sysdeps/unix/sysv/
sysdeps/unix/
sysdeps/posix/
sysdeps/generic/                       (最通用)
```

### multiarch 机制

- 运行时检测 CPU 特性（SSE4.2、AVX2、AVX-512 等）
- 通过 IFUNC 解析器选择最优实现
- 例: `memcpy` 可能有 SSE2、AVX2、ERMS 等多个版本

## 3. gmon — 性能分析支持

### 功能概述

`gmon` 模块为 `gprof` 工具提供运行时数据收集支持，
通过采样和调用计数生成性能分析数据。

### 规模

- 源文件: 13 个 .c 文件

### 主要 API

| 函数 | 说明 |
|------|------|
| `monstartup` | 启动性能分析 |
| `_mcleanup` | 结束分析并写出数据 |
| `mcount` | 函数调用计数（编译器插入） |
| `profil` | 采样式分析 |

### 工作流程

1. 程序编译时 `-pg` 选项使编译器在每个函数入口插入 `mcount` 调用
2. `monstartup` 设置采样缓冲区和计时器
3. 运行期间收集调用图和 PC 采样
4. 退出时 `_mcleanup` 写出 `gmon.out`
5. `gprof` 工具分析 `gmon.out` 生成报告

## 4. setjmp — 非局部跳转

### 功能概述

`setjmp` 模块实现保存和恢复执行上下文的函数，
用于异常处理和非局部跳转。

### 规模

- 源文件: 14 个 .c 文件，1 个 .h 文件

### 主要 API

| 函数 | 说明 |
|------|------|
| `setjmp` | 保存执行上下文（含信号屏蔽字） |
| `_setjmp` | 保存执行上下文（不含信号屏蔽字） |
| `sigsetjmp` | 条件保存信号屏蔽字 |
| `longjmp` | 跳转回保存的上下文 |
| `siglongjmp` | 带信号恢复的跳转 |

### 实现说明

- 保存/恢复的内容: 栈指针、程序计数器、被调用者保存寄存器
- 架构特定实现（汇编代码在 `sysdeps/` 中）
- `jmp_buf` 的大小因架构而异
- 包含指针加密保护（防止 ROP 攻击）

## 6. argp — 参数解析

### 功能概述

`argp` 实现 GNU 风格的命令行参数解析，自动生成 `--help` 和 `--version` 输出。

### 规模

- 源文件: 15 个 .c 文件，3 个 .h 文件

### 主要 API

| 函数 | 说明 |
|------|------|
| `argp_parse` | 解析命令行参数 |
| `argp_help` | 输出帮助信息 |
| `argp_error` | 报告解析错误 |
| `argp_failure` | 报告致命错误 |
| `argp_state_help` | 在解析过程中输出帮助 |

### 特点

- 自动生成格式化的帮助文本
- 支持嵌套选项组（子解析器）
- 与 gettext 集成实现帮助文本国际化
- 支持长选项和短选项

## 7. soft-fp — 软件浮点

### 功能概述

`soft-fp` 模块为没有硬件 FPU 的平台提供纯 C 实现的 IEEE-754 浮点运算。

### 规模

- 源文件: 104 个 .c 文件，12 个 .h 文件

### 提供的运算

| 类别 | 示例函数 | 说明 |
|------|----------|------|
| 加法 | `__adddf3`, `__addsf3` | 浮点加法 |
| 减法 | `__subdf3`, `__subsf3` | 浮点减法 |
| 乘法 | `__muldf3`, `__mulsf3` | 浮点乘法 |
| 除法 | `__divdf3`, `__divsf3` | 浮点除法 |
| 比较 | `__eqdf2`, `__ltdf2` | 浮点比较 |
| 定点转换 | `__fixdfsi`, `__fixsfdi` | 浮点→整数 |
| 浮点转换 | `__floatsisf`, `__floatdidf` | 整数→浮点 |
| 截断 | `__truncdfsf2` | double→float |
| 扩展 | `__extendsfdf2` | float→double |

### 使用场景

- 嵌入式系统（无 FPU）
- 内核早期启动（FPU 未初始化）
- GCC 编译器运行时库支持

## 8. nscd — 名称服务缓存守护进程

### 功能概述

`nscd` (Name Service Cache Daemon) 缓存 NSS 查询结果，
减少对后端数据源（DNS、LDAP、NIS 等）的重复查询。

### 规模

- 源文件: 35 个 .c 文件，5 个 .h 文件

### 缓存的数据库

| 数据库 | 缓存内容 |
|--------|----------|
| passwd | 用户信息（getpwnam/getpwuid） |
| group | 组信息（getgrnam/getgrgid） |
| hosts | 主机名解析（gethostbyname/getaddrinfo） |
| services | 服务端口（getservbyname） |
| netgroup | 网络组 |
| initgroups | 附属组列表 |

### 架构

```
┌────────────┐    ┌─────────────┐    ┌──────────┐
│ 应用程序   │───→│ nscd 客户端 │───→│ nscd 守护│
│ (libc)     │    │ (共享内存)   │    │ 进程     │
└────────────┘    └─────────────┘    └──────────┘
                                          │
                                     ┌────┴────┐
                                     │ NSS 后端│
                                     └─────────┘
```

### 配置文件

`/etc/nscd.conf` 控制:
- 各数据库的缓存开关
- 缓存条目的 TTL
- 正面/负面缓存策略
- 最大缓存条目数

> ⚠️ 注意: 现代系统倾向于使用 `systemd-resolved` (DNS) 和 `sssd` 替代 nscd。
